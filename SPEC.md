# `Pion` Language & Self-Hosting Compiler Specification (v0.1 Bootstrap)

`Pion` is an Agent-friendly, C-speed, fast-compiling, memory-safe, natively multithreaded systems programming language whose core syntax is a clean, strict subset/evolution of MoonBit.

This spec is the **single source of truth** shared by `runtime/`, `vendor/qbe/`, and `compiler/`. Any change to ABI, runtime symbols, grammar, or JSON schema must update this file in the same commit.

---

## 1. Design Pillars

1. **Zero Cross-Function Inference (Gojo rule)**: Every top-level `fn` and method MUST declare explicit parameter types and return type. Local `let` bindings infer types within the function body only. No macros, no `comptime`, no higher-kinded types.
2. **Second-Class References & Biased RC (Gojo + Koka/Lean 4)**:
   - No Rust-style `<'a>` lifetime annotations.
   - Heap objects (strings, bytes, arrays, maps, structs, enums, closures) use **Biased Reference Counting**: non-atomic `local_rc` on the owning thread (zero atomic overhead in single-threaded code), transparently promoted to atomic `shared_rc` when frozen/shared across threads.
   - Borrowed function parameters do not bump RC on entry/exit (Perceus-lite borrow elision).
   - **Perceus-lite last-use early drop**: top-level immutable owned heap locals in a straight-line statement block are released immediately after their last syntactic mention (`pion_rc_dec` + slot zeroing) when not pinned by a borrowed array-element view or borrowed immutable struct field-chain binding, reclaiming large temporaries before subsequent allocations.
   - **Abort-only panic invariant (Native SSA RC elision)**: the runtime abort primitives `pion_panic` and `pion_panic_oob` (`runtime/pion_rt.h`, `__attribute__((noreturn))`) are strictly non-returning process aborts (`abort()`/`_exit(1)`), never recoverable unwinds. Native QBE SSA post-pass (`inline_rc.pion`, never executed on `wasm32`) relies on this invariant to cancel matched `pion_rc_inc(%x)` / `pion_rc_dec(%x)` pairs across single-predecessor forward trap branches (`jnz %c, @trap, @next` where `@trap` contains only pure register ops, safe non-RC-header loads, exact `$pion_panic`/`$pion_panic_oob` calls, and `hlt`, and `@next` has `pred_count == 1` with no `phi`). If recoverable panics / unwinding are ever introduced in the future, trap-branch RC pair penetration MUST be disabled in lockstep. The diagnostic env toggle `PION_J2_DISABLE` (`1`/`2`/`3`/`3a`/`3b`/`all`) applies to single-package and unit-mode `pionc build`/`run` benchmark paths (not `pionc test`).
3. **Compile-Time Data-Race-Free Multithreading**:
   - Native OS threads via structured concurrency (`scope` + `spawn`), `Channel[T]`, `Mutex[T]`, `AtomicInt`.
   - Every type is statically classified as `Send` or `!Send`:
     - Primitives (`Int`, `Int64`, `UInt`, `UInt64`, `Double`, `Float`/`Float32`, `Bool`, `Byte`, `Int8`, `Char`, `Unit`), `String`, `ImmArray[T]` (where `T: Send`), the `World` capability (a frozen handle; spawned workers capture it explicitly to do IO/TCP), `Channel[T]` (where `T: Send`), `Mutex[T]` (where `T: Send`, or `T` is a *shareable container*: `Array[E]` or `Map[K, E]` with any valid `Map` key `K` — `String`, scalar integer/char/bool, or immutable pure-scalar tuple/POD struct — whose `E` is `Send` or itself a shareable container, e.g. `Mutex[Array[Rec]]`, `Mutex[Map[String, Array[String]]]`, `Mutex[Map[Int, String]]`, `Mutex[Map[Tri, String]]`; note `ImmArray[E]` is NOT a `Mutex` shareable container, so `Mutex[ImmArray[Array[Int]]]` is `!Send`), `AtomicInt`, and immutable `struct`/`enum` (no `mut` fields, all fields `Send`) are `Send`.
     - Any `struct` with `mut` fields, `Array[T]`, `FixedArray[T]`, `ImmArray[T]` where `T: !Send`, `Bytes`, `Map[K, V]` are `!Send` by default (must be wrapped in `Mutex[T]` or explicitly transferred via `move` with single-function linear check). A container placed in a `Mutex` (`Mutex::new` / `set`) or an `ImmArray[T]` sent across threads (`spawn` capture, `Channel::send`, `Mutex::new`/`set`) is frozen recursively together with its elements, and every object later stored into a frozen container (`pion_map_set`, array push/store, including the inline push fast path) is frozen on insertion, so elements released on any thread keep an atomic RC. Bare `Array` / `Map` outside a `Mutex`, `Ptr` and closures stay `!Send`.
     - Capturing a non-`Send` variable in `spawn` or sending a non-`Send` value over `Channel[T]` is a compile-time error (`E_NOT_SEND`).
4. **Explicit Capability (`World`, Vercel Zero rule)**:
   - Pure functions cannot perform IO, read wall clock, spawn OS processes, or touch the filesystem unless a `World` (or sub-capability) parameter is explicitly in scope.
   - Entry point: `pub fn main(world : World) -> Int` (or `fn main() -> Unit` in pure test mode). Calling IO builtins (`io_println`, `fs_read`, `fs_write`, `clock_now_ms`, `proc_exec`, `env_get`, `args_get`) without a `World` value in scope is a compile-time error (`E_CAPABILITY_MISSING`).
   - Network and time primitives (`tcp_listen`, `tcp_local_port`, `tcp_accept`, `tcp_connect`, `tcp_read`, `tcp_write`, `tcp_close`, `sleep_ms`) take the `World` value as their **explicit first argument**; a `World` merely in scope is not enough (`E_CAPABILITY_MISSING`).
   - Function/method attributes `#no_io` / `#[no_io]` and their alias `#render_thread` / `#[render_thread]` enforce a compile-time zero-`World` boundary (intended for GUI render threads and non-blocking callbacks): annotated functions, `impl` methods, and any nested closures inside them cannot accept a `World` parameter, reference a `World` binding, or call `World` IO builtins / runtime primitives / `scope` (`E_NO_IO_VIOLATION`, with no `world : World` insertion edit). Non-`World` `extern "C"` FFI, `Channel`, `Mutex`, `AtomicInt`, and pure computation remain allowed.
5. **Agent-First Compiler Interface**:
   - `pionc check --json <path>` — compact JSON diagnostics (`file`, `line`, `col`, `code`, `message`, `expected`, `found`, `fixit`, plus machine-applicable `edits` when an exact patch is known), one object per diagnostic inside `{"ok":bool,"diagnostics":[...]}` (§5.1).
   - `pionc query defs|sig|callers|deps|analyze --json <path>` — structured symbol table, exported signatures, call graph, package dependency graph, and typed analysis export (`types`, `fns`, `closures`); `<path>` may be a file, a package directory, or a whole `pion.toml` workspace (§5.2).
   - `pionc test --json <workspace>` runs every local package's tests in one report (§5.3); `pionc init <dir>` scaffolds a package that is check/test/run/fmt-clean; `pionc fetch [dir]` resolves git dependencies and writes `pion.lock`; `pionc add` / `pionc update` edit `pion.toml` and re-resolve from paths, git URLs or a git-index registry, and `pionc search` queries a registry's package catalog (§6).
   - `pionc doc [--json] <path>` — the public API (every `pub` struct/enum/trait/extern fn/fn/const and every `impl`) of a file, directory or whole `pion.toml` workspace in one call (§5.4).
   - Contracts: `debug_assert(cond, msg)` — active in dev/test builds, stripped to 0 bytes in `--release`; it is an expression of type `Unit` and may stand in expression position (e.g. a `match` arm body).
6. **Sub-150ms Incremental Compile, Tiny Binaries, Zero `target/`**:
   - Package-level separate compilation via `.pionsig` compact interface files: editing a function body without changing its `pub` signature yields 100% cache hit on downstream packages.
   - **Global Content-Addressed Cache** (`$PION_CACHE_DIR`, default `~/.cache/pion/cas`), LRU-evicted (`$PION_CACHE_MAX_MB`, default 2048). **NEVER writes a `target/` or `_build/` directory inside the source tree.**
   - **Dev backend**: emits per-package **QBE IL** → vendored `qbe --obj` writes the object file directly for `arm64_apple` (Mach-O arm64) and `amd64_sysv` (ELF64 x86-64) with no `as`; all other targets (`amd64_apple`, `amd64_win`, `arm64`, `rv64`, `ios_arm64`, `ios_sim_arm64`, `android_arm64`, `android_x64`) lower via `qbe -t <arch>` → target `cc -c` → `ld`/`cc` + prebuilt `<64 KB` `libpionrt.a`. `--emit-asm` or `PION_NO_DIRECT_OBJ=1` falls back to `qbe` text + assembler.
     - **Strict `jnz`/`jtbl` `w`-class codegen invariant**: because QBE `jnz`/`jtbl` inspects only the low 32 bits of its argument, Pion codegen (`qbe.pion`) MUST pass only `Kw` (`w`-class) temporaries (or constants) to every `jnz` and `jtbl` (testing 64-bit pointers, lengths, booleans, and `%tp_*` generic flags via explicit `=w cnel %x, 0` first). Vendored `qbe` preserves upstream default semantics for Stage 0 seed compatibility and adds an explicit strict gate (`--strict-jnz` / `-strict-jnz` / `PION_QBE_STRICT_JNZ=1`) that rejects any non-`w` temporary operand to `jnz`/`jtbl`; `pionc` passes `--strict-jnz` on every QBE invocation and `wasm.pion` enforces the equivalent `WASM_TY_I32` check on every `jnz`/`jtbl` at module entry.
   - **Multi-target & library outputs**:
     - Host auto-detection (`$PION_TARGET`, else `$OS == Windows_NT`, else `uname -sm`): macOS ARM64 (`arm64_apple`), macOS x86_64 (`amd64_apple`), Linux x86_64 (`amd64_sysv`), Linux ARM64 (`arm64`), Linux RISC-V 64 (`rv64`), Windows x86_64 (`amd64_win`).
     - Cross targets: `--target arm64_apple|amd64_apple|amd64_sysv|amd64_win|arm64|rv64|ios_arm64|ios_sim_arm64|android_arm64|android_x64|wasm32`, with optional `--sysroot <dir>` (`-isysroot` on Apple, `--sysroot=` on ELF; iOS defaults to deployment target `16.0` overridable via `$PION_IOS_DEPLOYMENT_TARGET`/`$IPHONEOS_DEPLOYMENT_TARGET` and auto-probes `xcrun --sdk iphoneos|iphonesimulator --show-sdk-path`; Android auto-probes `$PION_ANDROID_CC`, `$ANDROID_NDK_HOME`, `$ANDROID_NDK_ROOT`, `$ANDROID_HOME/ndk`, `$ANDROID_SDK_ROOT/ndk`, `$HOME/Library/Android/sdk/ndk`, `$HOME/Android/Sdk/ndk`, and fails cleanly if no NDK/CC is configured; cross targets with unset `PION_RT_LIB` auto-compile and cache `runtime/pion_rt.c` as a target-specific `.a` in CAS; Windows auto-links `-lws2_32`, links executables with a 16 MB main-thread stack (`-Wl,--stack,16777216`; MinGW defaults to 1 MB), spawns `scope` threads with 8 MB stacks, and omits `-fPIC`/`-rpath`; when `CC` targets Windows MSVC (`PION_WIN_ABI=msvc`, `clang-cl`, or `cc -dumpmachine` containing `msvc`), `pionc` auto-derives `clang++`, translates `-mwindows`/`-mconsole`/`-Wl,--stack,N` to `/SUBSYSTEM:*`/`/STACK:*`, adds `-fuse-ld=lld`, omits `-lm`/`-lpthread`, passes `qbe --seh` so every framed Win64 function carries Microsoft x64 unwind tables (`.pdata`/`.xdata` attached to associative COFF COMDAT `one_only,<sym>` sections, which `lld-link /OPT:REF` keeps for live functions and drops with dead functions; MinGW builds omit them because GNU ld `KEEP()`s every `.pdata` and would defeat `--gc-sections`), and auto-compiles `runtime/pion_rt.c` into CAS when `PION_RT_LIB` is unset). `amd64_win` code follows the Microsoft x64 ABI: `xmm6`–`xmm15` (all 128 bits) and `rbx rbp rdi rsi r12`–`r15` are callee-saved, `%rsp` is 16-byte aligned after every prologue, and the prologue order (pushes, one allocation, `%rbp` frame at offset 0, `movups` xmm saves) is the one the unwind codes describe.
     - **WebAssembly (`--target wasm32`)**: zero-toolchain direct `.wasm` binary emission from QBE SSA (`compiler/src/core/wasm.pion`) requiring no `emcc`/`wasi-sdk`/`wasm-ld`; runs in Browser and Node.js via the zero-dependency ES module `runtime/pion_wasm_rt.mjs` (`pionc run --target wasm32` invokes `node runtime/pion_wasm_rt.mjs` with `$PION_WASM_RT` override) using byte-for-byte identical linear-memory layouts to 64-bit `pion_rt.h`. Bidirectional runtime ABI handshake (`PION_WASM_RT_ABI = 2`): emitted modules export immutable `i32` global `__pion_wasm_rt_abi = 2` (checked by `bindExports`, throwing on mismatch) and non-zero-import modules import zero-arg sentinel `pion_rt.__pion_rt_abi_v2` pinned via the Wasm `start` section (Section 8) so `wasm-opt -Oz` never strips it, causing stale `pion_wasm_rt*.mjs` hosts to fail immediately with `WebAssembly.LinkError`. Optional `--wasm-names` (on `pionc build`/`run`, default off for zero `--release` overhead) appends the standard WebAssembly `name` custom section (subsection `1`, Function Names; preserved via `wasm-opt -g` when `wasm-opt` is active) for CPU profiling and per-function size analysis, and is included in the Wasm32 binary CAS key.
        - **Web Wasm Official Host Bridge (`runtime/pion_wasm_rt_web.mjs`) & `--emit-web-rt`**: `pionc build --target wasm32 --emit-web-rt [<path.mjs|.js>]` (or `--emit-web-rt=<path.mjs|.js>`; the destination path must end with `.mjs` or `.js` ASCII case-insensitively and must not be an existing directory; bare `--emit-web-rt` only consumes the next argument when it does not start with `-` and ends with `.mjs`/`.js`, otherwise uses the default output `<dir_of_-o>/pion_wasm_rt_web.mjs` or `./pion_wasm_rt_web.mjs` when `-o` is omitted; rejected on non-`wasm32` targets or when the POSIX symlink-resolved, ASCII case-folded destination collides with any build output, input path, or loaded source file) emits the compiler-matched `pion_wasm_rt_web.mjs` (verifying that the first non-whitespace, non-comment statement is `export const PION_WASM_RT_ABI = <WASM_RT_ABI_VERSION>;` terminated by `;`; located via `$PION_WASM_WEB_RT`, sibling of `$PION_WASM_RT`, `share/pion/pion_wasm_rt_web.mjs`, or `runtime/pion_wasm_rt_web.mjs`). Each `createPionRuntime(opts)` instance exports strictly instance-bound helpers (zero module-global shared state): `readStr(obj)` / `readUtf8(obj)` (alias, returns JS `string`), `mkStr(jsStr)` (returns `RC=1` Pion `String` handle; release via `rcDec(obj)` or pass to a consuming Pion function), `mkCStr(jsStr)` (allocates NUL-terminated UTF-8 raw buffer returning `BigInt` `Ptr`; release via `freePtr(ptr)`), `readBytes(obj)` (returns an independent copied `Uint8Array`, safe across `memory.grow`), `mkBytes(uint8Array)` (copies via `new Uint8Array(src)` first if the input view aliases the runtime's own Wasm linear memory, then returns an `RC=1` Pion `Bytes` handle; release via `rcDec(obj)` or Pion ownership transfer), `freePtr(ptr)`, `rcDec(obj)`, `rcInc(obj)`, and `syncMemory()`. `createPionRuntime({ extraImports, hostFns })` merges custom host import namespaces via `extraImports` (throwing an `Error` if `extraImports` attempts to override the reserved `pion_rt` namespace, preserving `__pion_rt_abi_v2` enforcement) and registers `extern "C" fn` host callbacks into `imports.pion_rt` via `hostFns` (throwing if any key overrides a built-in `pion_rt` symbol or is not a function).
        - **Wasm32 Math & `Double::to_string()` Parity**: both `pion_wasm_rt.mjs` and `pion_wasm_rt_web.mjs` export the full f64/f32 `libm` symbol set (`sqrt`/`sqrtf`, `cbrt`/`cbrtf`, `pow`/`powf`, `exp`/`expf`, `log`/`logf`, `log1p`, `sin`/`sinf`, `cos`/`cosf`, `tan`/`tanf`, `atan2`/`atan2f`, `asin`/`asinf`, `acos`/`acosf`, `atan`/`atanf`, `fabs`/`fabsf`, `floor`/`floorf`, `ceil`/`ceilf`, `round`/`roundf`, `trunc`/`truncf`, `fmod`), explicitly aligning C99 Annex F `pow`/`powf` edge cases (`pow(1, NaN) == 1.0`, `pow(-1, ±Inf) == 1.0`, `pow(x, ±0) == 1.0` for both `Double` and `Float`) and C99 `round`/`roundf` tie-away-from-zero semantics (including `0.49999999999999994 -> 0.0`). `Double::to_string()` formats any NaN (positive or negative) canonically as `"nan"` on both Native (`pion_rt.c`) and Wasm32; `formatG` / `fmtG` decodes IEEE-754 64-bit bits directly with exact `BigInt` decimal expansion, strict round-half-to-even, and post-rounding `%g` scientific-notation threshold switching (`e10 < -4 || e10 >= prec`), matching Native C locale `snprintf("%.*g", 15..17)` byte-for-byte.
      - **Artifact Panic/Assert Source Path Sanitization**: frontend diagnostics and fix-it `edits` (`pionc check --json`) always preserve original real file paths (`sp.file`). At codegen time (`qbe.pion`, covering both Native and Wasm32), embedded source-file string constants for `panic`, `abort`, `debug_assert`, `unwrap`, division/shift traps, `guard`, and non-exhaustive `match` are component-normalized (`\` → `/`, `.` and internal `..` folded) to POSIX `"<pkg>/<pkg_rel_path>"` (e.g. `pkg_a/src/lib.pion`; strict basename for bare non-package files) so compiled artifacts never embed host absolute directories. Package CAS keys are unchanged.
     - Artifact modes: `--emit-obj <out.o>`, `--emit-staticlib <out.a>` (archives package + `-fPIC` `c_sources` `.o` via `$AR` / `llvm-ar` / `<triple>-ar` / `ar`), `--emit-cdylib <out.so|.dylib>` (`-dynamiclib` on Apple, `-shared` + `-fPIC` on Linux/Android with `STV_HIDDEN` internal symbols for `-Wl,-Bsymbolic`-free shared linking), `--emit-asm <out.s>` (skips assembly when no link/object artifact is requested). `pub extern "C" fn` entry points idempotently initialize package and transitive dependency constants on first call.
     - Entry point overrides (`pionc build`): `--entry-symbol <name>` renames the generated `$main` wrapper symbol to `$<name>` (retaining `$pion_world_init`, transitive `init_consts`, user `main`, and `$pion_rc_dec`); `--no-main` omits the `$main` wrapper entirely (mutually exclusive with `--entry-symbol`). Both are part of the package/unit CAS key.
   - **Native libraries**: `-l <lib>` / `-l<lib>` / `--link <lib>` on `build`/`run`/`test`, plus `[link] libs = [...]` in `pion.toml` (dependencies first, de-duplicated) add `-l<lib>` to the link; the list is part of the binary's cache key. In `--release` mode, `[link] c_sources` automatically receive `-O3` unless `cc_flags` already specifies an `-O*` / `/O*` optimization flag.
   - **Release backend** (`--release`): the same embedded QBE pipeline (no LLVM, no separate optimizing toolchain) with release-mode IL, stripping `debug_assert`.
   - **Encapsulation, field mutability, enum methods & scoped testing**:
     - Struct fields are immutable by default unless declared `mut`; assigning (`=` / `+=` / etc.) or taking a `mut` argument of a non-`mut` struct field is a type error (`E_TYPE_MISMATCH`).
     - Fields of a `pub struct` remain readable across packages by default; prefixing a field with `priv` (e.g. `priv scalar : Bytes`, `priv mut state : Int`) restricts cross-package reads, writes, and direct struct literal construction (`E_PRIVATE_FIELD`) while permitting access inside the defining package.
     - Inherent methods (`pub fn EnumName::method(self : EnumName, ...) -> R`) and trait impl methods are supported on `enum` types via both dot-call (`e.method(...)`) and path-call (`EnumName::method(e, ...)`, whenever the member is not a variant name).
     - `pionc test [--no-deps | --only-pkg]` runs tests only for the target root package (or direct workspace members for a virtual workspace), skipping dependency package tests while still compiling and linking dependencies. Multiple `pion.toml` package/workspace directories may be passed (`pionc test dir1 dir2 ...`) and are tested in order (deduplicated by normalized path; mixing manifest directories with bare `.pion` files is rejected).
    - **Dependency aliases (`package = "..."`), canonical package IDs (`canon_id`) & multi-source coexistence**:
      - `[dependencies]` and `[workspace.dependencies]` accept an optional `package = "orig_name"` key (Cargo-style dependency renaming), e.g. `my_json = { package = "json", git = "...", tag = "v1" }`, `my_json = { package = "json", path = "../vendor/json" }`, or `{ workspace = true }` (inheriting the workspace entry's `package`, or aliasing a `[workspace.dependencies]` entry via `my_json = { package = "json", workspace = true }`). `package = "..."` MUST be paired with an explicit source (`path`, `git`, `registry`, or `workspace = true` inheriting one); a bare `version` key alone is never a package source. After loading the target directory's `pion.toml`, its declared `[package].name` MUST equal the expected original package name (`dep.package` if set, else `dep.name`).
      - **Node identity vs. dependency edge alias**: aliases are strictly edge attributes (`dep_alias -> target_canon_id` in `import_aliases`) and never determine package identity. Each package node has a deterministic `source_id` that never embeds host absolute paths:
        - Git dependencies (including relative `path` dependencies inside the same git checkout): `git|<normalized_git_url>|<locked_rev>|<normalized_subdir>|<declared_name>`. Workspace DFS deduplicates by `source_id` (while reusing the read-only `checkouts/<rev>` directory), so distinct Git URLs pointing to the same commit remain independent nodes regardless of manifest order.
        - Local `path` dependencies: `path|<rel_locator_from_anchor>|<declared_name>`, where both the anchor root (enclosing `[workspace]` root or standalone root package directory) and target directory are symlink-canonicalized (`pion_fs_canon_path`) before computing `rel_locator`, ensuring real paths and directory symlinks to the same directory yield one `source_id` and one `canon_id`. Paths escaping above the root remain relative `../...` without host prefixes. 100% cross-worktree CAS HIT applies to pure-Pion relative `path` / remote `git` / `registry` dependencies (`c_sources` keys use Direct Mode compiler header dependencies and content hashes with zero `mtime`, and local `file://` git URLs remain part of `source_id`).
      - **Canonical ID (`canon_id`)**: the standalone/hybrid root package (`rel_locator == "."`) keeps `canon_id = declared_name`; every other package (local path dep, workspace member, or git dep) gets `canon_id = declared_name + "__" + sha256(source_id)[0..8]`, independent of aliases, traversal order, or whether another same-named package exists in the graph. Consequently: (1) diamond dependencies referencing the same physical source under different aliases resolve to one `canon_id` and share identical exported types; (2) same-named packages from different sources get distinct `canon_id`s, zero QBE symbol/CAS collisions, and distinct nominal types; (3) adding/removing an unrelated same-named dependency never alters other packages' symbols or CAS keys; (4) `extern "C" fn ... { ... }` C export symbol collisions across packages are rejected at compile time with `E_DUPLICATE_C_SYMBOL`.
      - External git-cache packages' unaliased relative `path` dependencies still unify onto a unique unaliased root/workspace pin when present (`root_pins` never folds explicitly aliased or multi-source dependencies).

## 2. Self-Hosting Architecture (Pure Pion, Zero External Compiler Dependency)

`Pion` is 100% self-hosted in pure `.pion` with zero MoonBit or LLVM dependency:

```
bootstrap/
  pionc-seed.ssa.gz        # Architecture-independent QBE SSA Stage 0 seed (gzip -9 -n)
compiler/
  src/
    core/                  # Pure Pion compiler core & native unit tests (*_test.pion)
      lexer.pion
      ast.pion
      parser.pion
      sig.pion             # .pionsig serializer/deserializer
      types.pion           # Type checker + exhaustive match + Send + World capability + `mut` arguments + ResolvedInfo side tables
      verify.pion          # `#verify` static rules (move / borrow / escape / closure / forbidden types)
      llbc.pion            # Pion-LLBC: desugared verification IR of the `#verify` closure (§3.5)
      lean.pion            # functional lowering + Lean 4 emitter of `pionc extract-lean` (§3.5)
      mutarg.pion          # codegen lowering of `mut self` receivers to in-out places
      qbe.pion             # QBE IL emitter (arm64_apple & amd64_sysv)
      cas.pion             # Global CAS hashing & LRU cache manager
      diag.pion            # JSON diagnostics
      query.pion           # Symbol/signature/call-graph/workspace query engine
      fmt.pion             # Deterministic formatter
      manifest.pion        # pion.toml / pion.lock / registry parser
    cli/                   # Pure Pion native CLI driver (main.pion, World + parallel scope/spawn)
```

- **Stage 0 (`pionc0`)**: Decompress `bootstrap/pionc-seed.ssa.gz` and compile it with the embedded C11 `qbe` + `runtime/libpionrt.a` + system `cc` → `out/pionc0` (requires only a C11 compiler; works natively on macOS ARM64, Linux x86_64, and Linux ARM64).
- **Stage 1 (`pionc1`)**: `pionc0 build` compiles `src/core` + `src/cli/main.pion` → `out/pionc1`.
- **Stage 2 (`pionc2`)**: `pionc1 build` compiles `src/core` + `src/cli/main.pion` → `out/pionc2` (using `Pion`'s own native multithreaded package compilation).
- **Fixed-Point Proof**: QBE IL & assembly emitted by `pionc1` vs `pionc2` for `pionc` itself MUST be **bit-for-bit identical** (SHA-256 match). On Linux x86_64, Stage 3 == Stage 4 is likewise bit-for-bit identical across `.ssa`, `.s`, and direct `qbe --obj` ELF64 `.o` (zero `as`).

## 3. Core Language Grammar

### 3.1 Lexical Elements
- Comments: `// line comment` (including `///|` block separators ignored as comments).
- Identifiers: `[a-zA-Z_][a-zA-Z0-9_]*`
- Literals:
  - `Int`: decimal `42`, hex `0xFF`, negative `-1`
  - `Int64`: `42L`, `0xFFL`
  - `UInt`: unsigned 32-bit `42U`, `0xFFFF_FFFFU` (and unsuffixed integer literals when expected type is `UInt`)
  - `UInt64`: unsigned 64-bit `42UL`, `0xFFFF_FFFF_FFFF_FFFFUL` (and unsuffixed integer literals when expected type is `UInt64`)
  - `Double`: `3.14`, scientific notation `1e-9`, `1.5E+3`

Before its type is fully refined, any use of a pending binding that does not fully determine its type—except zero-argument built-in queries (`length`, `is_empty`, `clear` on `Array`, `FixedArray`, `ImmArray`, or `Map`, and `is_none`, `is_some` on `Option`) and pure tag-only `Option` checks (`is None` / `is Some(_)` or `match` arms using only `_`, `None`, `Some(_)` without binding any payload or whole value)—fails closed immediately with `E_MISSING_TYPE` (including plain value reads/aliases `let m2 = m`, field access `m.keys`, passing to unconstrained parameters, array/tuple elements, untyped indexing `let x = xs[0]`, assignments/indexed assignments with unresolved operands, and any user-defined method call that leaves receiver type parameters unresolved). Likewise, any non-diverging generic call whose unbound type parameter carries a trait bound, appears in the return type or a non-`self` parameter type, or participates in body `Eq`/`Map`-key/operator obligations fails closed with `E_MISSING_TYPE` unless resolved by context or deferred binding refinement (e.g. `ignore(None)` requires a type annotation, whereas unconstrained phantom type parameters with no bounds or body obligations are permitted). In array literals whose leading element is under-specified (such as `[None, Some(x)]`), the first concrete element refines the array's element type and rechecks subsequent elements against it.     2. The iteration count is fixed to `init_len = arr.length()` sampled once at loop entry (elements pushed during the loop are not visited).

- Ordering & generic operator instantiation constraints:
  - Unary `-` requires a numeric type (`Int`, `Int64`, `UInt`, `UInt64`, `Double`, `Float`, `Byte`, `Int8`); non-numeric operands (including `String`, `Bool`, structs, enums, containers, `Unit`) are rejected with `E_TYPE_MISMATCH`.

Constraints propagate transitively across arbitrarily deep generic call chains and across packages (including private generic helpers); any concrete instantiation that violates a constraint is rejected at the call site with `E_TYPE_MISMATCH`, and valid instantiations are monomorphized so every concrete type uses its exact native/Wasm32 ABI and semantics.
- Must-use `Result` & `-> Unit` implicit tail discard: when a function, closure, block, `if`, or `match` arm expects `Unit`, a non-`Result` tail expression is implicitly discarded (with RC release for heap values) so builder chains and side-effect calls do not require `let _ = ...`. An expression statement whose type is `Result[T, E]` and whose value is discarded — any non-tail statement of a block, or the tail statement of a `-> Unit` body, loop, or `test` body — is still a compile-time error (`E_UNHANDLED_RESULT`, fix-it "handle the Result with `match`, `?`, or explicitly discard with `let _ = ...`"). `let _ = expr` discards explicitly; a block's tail value returned to a non-`Unit` function or branch is not discarded.

### 3.4 Second-Class `mut` Parameters, `#into` Call-Site Conversions & `#verify`

**Opt-in single-hop `#into` conversions (`into` parameters & `?`).**
- **Contextual `into` parameter modifier**: `into p : T`, `into w~ : T = def`, and `into opt? : T` opt that parameter into single-hop call-site conversion. `into` is a contextual keyword only in parameter position (`let into = 42` and `fn f(into : Int)` remain valid). Combining `into` with `mut` (`into mut` / `mut into`) or using `into` on `extern "C" fn` or closure parameters is `E_PARSE`. Callees keep concrete non-generic ABIs (zero monomorphization bloat); function pointer types `(Target) -> R` and `dyn Trait` are unaffected.
- **`#into` / `#[into]` converters**: placed on an inherent static function on the target type (`#into [pub] fn Target::from_xxx[T...](v : Src) -> Target`) or an inherent instance method on the source type (`#into [pub] fn Src::to_xxx[T...](self : Src) -> Target`). Violations report `E_INVALID_INTO`: must be defined on a local `struct`/`enum` (not a free `fn` or `impl` method), must take exactly 1 plain positional non-`mut` non-`World` parameter, and must either have `self : Src` (instance method) or return `Target` / `Target[...]` (static function). `#into` and `into` propagate across packages via `.pionsig v1` and `.pionstub`.
- **Strict 3-source lookup scope** (never scans unrelated imported packages):
  1. Target type `Target`'s defining package (`Target::*` static `#into` functions; cross-package requires `pub`);
  2. Source type `Src`'s defining package (`Src::*` instance `#into` methods; cross-package requires `pub`);
  3. Compiler built-in zero-overhead table: `String -> StrView` (`.as_view()`) and `Bytes -> BytesView` (`.as_view()`).
- **Trigger sites, strict 1-hop & two-tier deterministic priority**: triggers only when `Src != Target` (`Src == Target` passes through with zero conversion) at (1) direct function/method/Pion-JSX calls on parameters marked `into` (including `into opt? : Target` called as `opt=src`, which converts `src` to `Target` before wrapping in `Some(...)`), and (2) `expr?` (`ETry`) on `Result[A, E1]` inside a function returning `Result[B, E2]`. Never chains `A -> B -> C`. Matching candidates are partitioned into **Tier 1** (source parameter type is not a bare type parameter `T`, plus built-ins and `self` methods) and **Tier 2** (source parameter type is a bare type parameter `T`, e.g. `Live::of_value[T](v : T) -> Live[T]`). A unique Tier 1 match wins over Tier 2; if Tier 1 is empty, a unique Tier 2 match is chosen; `>= 2` matches in the winning tier report `E_AMBIGUOUS_INTO` listing all conflicting candidates; 0 matches report `E_TYPE_MISMATCH`.
- **Pion-JSX synergy**: `prop=>{ expr }` remains lexically explicit (`prop=fn() { expr }`); when passed to an `into` parameter (e.g. `into text~ : Live[String] = .Is("")`), unannotated closures infer their return type (using a unique `#into` `TFn` target hint when available) and match `#into` converters such as `Live::of_fn`.

**`mut` parameters (all code).** A parameter written `mut p : T` (top-level `fn`s, methods, trait methods and `impl` methods; `mut self` included) is an in-out parameter:
- It must be a plain positional parameter: `mut p~`, `mut p?`, `mut p : T = d`, `mut` on `extern "C" fn` parameters and on closure parameters are `E_PARSE`.
- Inside the body `p` is a mutable binding: `p = v`, `p.f = v`, `p[i] = v`, and passing `mut p` down are allowed. A closure may not capture a `mut` parameter (`E_TYPE_MISMATCH`; `E_VERIFY_CLOSURE_CAPTURE` in `#verify` code).
- Call sites pass `mut <place>` where a place is `x`, `x.f1.f2`, `a[i]` or a combination, rooted at a `let mut` binding or a `mut` parameter; a field written through it must be a `mut` field; an index must be a simple expression (locals, literals, fields, arithmetic; no calls). A method whose receiver is `mut self` is called as `recv.m(...)` without `mut`, and `recv` must be such a place. Violations are `E_TYPE_MISMATCH`: an immutable root (with the `let` → `let mut` edit), a plain argument for a `mut` parameter (with a `mut ` insertion edit for identifiers), `mut` for a non-`mut` parameter, a non-place, an argument type that is not exactly the parameter type. `mut <place>` anywhere else (an expression, a builtin's argument) is `E_TYPE_MISMATCH` (or `E_PARSE` outside an argument list).
- Aliasing (`E_VERIFY_ALIASING`, all code): within one call (receiver included), the place of a `mut` argument must not equal, contain or be contained in the place of any other argument (`f(mut a, mut a)`, `f(mut s, mut s.x)`, `f(mut s.x, s)`, `f(mut a[i], mut a[j])` are rejected; distinct fields `f(mut s.x, mut s.y)` are fine), and must not be rooted at a local read by another `mut` argument's index (`f(mut a[k], mut k)`).
- A function with `mut` parameters cannot be used as a first-class value (`E_TYPE_MISMATCH`); a trait with `mut` parameters is not object-safe for `dyn` (call it through a generic bound); an `impl` method's `mut` markers must match its trait's (`E_TRAIT_METHOD_SIGNATURE`).
- Evaluation: arguments (named ones included; named arguments are accepted by functions and inherent methods, not by trait-method calls) are evaluated left to right as written, then omitted default / optional arguments in parameter order; each default parameter expression is evaluated in the callee's package and generic context with only prior parameters (`0 .. p - 1`) in scope (never capturing caller locals); a `mut` argument's place is read at its position (the container and index of `a[i]`, or the object owning the field of `o.f`, are evaluated once, there, and the write-back targets that same element or field), and after the call returns every `mut` place is assigned the final value in argument order.

**ABI.** A `mut` parameter is passed as `l`: a pointer to a 64-bit value slot (uniform heap-slot encoding: `Int`/`UInt` as sign/zero-extended `l`, `Double` as `d` bits, objects as `PionObj*`). The caller moves the place's current value into a fresh `alloc8 8` slot, passes its address, and after the call assigns the slot's value back to the place (ordinary assignment semantics, so cells, fields and bounds-checked elements behave as `place = v`). The callee copies the slot into an ordinary owned local (retained) and, on every exit path, stores the local back into the slot and releases the slot's previous value. Functions with `mut` parameters are never inlined. The emitted IL is plain QBE (the Wasm32 backend treats the passed slot as escaping); this ABI is part of `PION_COMPILER_ABI_REV` `pionc-v0.17`.

**`#verify`.** A `#verify` function / method (or every method of a `#verify impl`, or every function of a `[verify] enabled = true` package, §6; `#verify_opaque` opts out) is additionally checked by these rules; non-`#verify` code is unaffected. Types are classified as **Forbidden** (`World`, `Ptr`, `Scope`, `Channel`, `Mutex`, `AtomicInt`, `Float`, `dyn Trait`, `ImmArray[U]` where `U` is Forbidden or Unique, or anything containing them), **Unique** (`Array`, `FixedArray`, `Bytes`, `StringBuilder`, `Map`, structs with a `mut` field, generic parameters, and anything containing a Unique type) or **Copy** (everything else: integers, `Double` as an opaque 64-bit bit pattern, `Bool`, `Byte`, `Char`, `Unit`, `String`, `ImmArray[C]` of a Copy type `C`, immutable structs / enums / tuples / `Option` / `Result` of Copy types).
- `E_VERIFY_UNSUPPORTED`: a Forbidden type in a parameter, the return type, a binding or an expression (reported once per type per function); `physical_equal(...)`; `black_box(...)` (a benchmarking barrier only; `bench_loop` is likewise rejected by Lean extraction); custom built-in `impl Eq` equality (`==`/`!=`, `.contains`, `#derive(Eq)` containers, generic forwarding, or `[T : Eq]` bounds reaching a custom `impl Eq` type, including cross-package; payload-less enums with custom `impl Eq` do not emit default `BEq` instances in Lean 4); floating-point `Double` literals / arithmetic / comparison operators (`==`/`!=`/`<`/`<=`/`>`/`>=`), `Map` keys containing `Double` or `Float` (including through generic instantiation), or non-bit-pattern methods on `Double` (only `Double::from_bits`, `.to_bits()`, `.reinterpret_as_uint64()`, `.reinterpret_as_int64()`, `.is_nan()`, `.is_inf()`, `.is_finite()`, `.compare(other)` with total-order semantics `NaN == NaN > +Inf > ... > +0.0 == -0.0 > ... > -Inf`, and `UInt64::reinterpret_as_double()` are allowed on `Double` in `#verify`); or shallow-copying / aliasing builtins on `Unique` elements (`Array::make`, `FixedArray::make`, `FixedArray::fill`, `FixedArray::blit_to`, `Array::copy`, `FixedArray::copy` require a `Copy` element type; `Map::copy` requires `Copy` key and value types; `Map::get` requires a `Copy` value type).
- `E_VERIFY_MOVE`: a Unique local is moved by `let y = x`, `y = x`, storage into a struct / enum / array / tuple literal or a storing builtin (`push`, `set`, `fill`, variant constructors), `Option::unwrap_or` / `Result::unwrap_or` on a `Unique` payload, `return` / tail position; moving a path `x.f` / `x[i]` moves `x` (and moving out of a compound `Unique` `EField` / `EIndex` or non-place `match` / `is` scrutinee consumes its operand). Reading a moved binding is an error; moves merge across `if` / `match` branches (moved on any non-diverging branch ⇒ moved after, and `match` arm guards carry their moves into later arms on fallthrough), short-circuit `&&` / `||` preserve pre-RHS moves, loop bodies propagate `continue` into C-style `for` step expressions and the next iteration and preserve both 0-iteration entry moves and `break` moves after the loop, and `x = new` revives `x`. `x.copy()` produces an owned copy for `Copy`-element containers.
- `E_VERIFY_BORROW_ESCAPE`: a non-`mut` Unique parameter is a read-only borrow (calls with non-`mut` parameters never consume the argument): it may be read, indexed, passed on read-only and `.copy()`ed (for `Copy`-element containers), but not written (field / element assignment, mutating builtins such as `push` / `pop` / `set` / `swap` / `clear` / `sort` / `fill` / `blit_to`) nor moved (bound by `let`, stored, returned, consumed by `unwrap_or` or a non-place `match` / `is` scrutinee). Mutating through a non-place receiver expression (such as `mk().push(1)` or `({ a }).push(1)`) is also rejected with `E_VERIFY_BORROW_ESCAPE`. Pattern and `for x in` bindings projected from a borrowed (or any place) Unique value are read-only too.
- `E_VERIFY_MUT_ESCAPE`: a `mut` parameter (or a Unique binding projected from it) cannot be moved out (bound by `let`, stored, returned); use `.copy()`.
- `E_VERIFY_CLOSURE_CAPTURE`: a closure may capture only immutable Copy bindings.
- `E_VERIFY_ALIASING` (borrowed views): while `for x in r` iterates (any element type) or a `match` arm / `is` branch / `guard ... is` binding holds a Unique part of a place rooted at `r`, `r` is pinned: writing through it (field / element assignment, mutating builtins, `mut self` calls), rebinding it, passing it as `mut <place>` or moving it is an error until the loop body / arm / branch / enclosing block ends.
- `E_VERIFY_UNVERIFIED_CALLEE`: `#verify` code may call `#verify` / `#verify_opaque` functions and methods, `extern "C"` functions, builtins, closures and trait-bound methods; calling an unmarked user function is an error (the marks travel in `.pionsig` / `.pionstub`). Instantiating a generic callee's bound `T : Trait` with a concrete type from `#verify` code requires every method of that `impl` to be `#verify` / `#verify_opaque`.
- Runtime arithmetic (only in `#verify` functions, so ordinary code keeps its codegen): integer `/` and `%` panic with `division by zero` when the divisor is 0 (including `Byte` and `Int8`), and signed `Int` / `Int64` / `Int8` `MIN / -1` and `MIN % -1` panic with `integer overflow in division`; `<<` / `>>` panic with `shift amount out of range` unless `0 <= rhs < 8` (`Byte`, `Int8`) / `32` (`Int`, `UInt`) / `64` (`Int64`, `UInt64`), comparing the count at its own width (a 64-bit count is never truncated, so `1L << (1L << 32)` panics). Other integer arithmetic wraps (two's complement for signed, 8-bit unsigned wrapping for `Byte` arithmetic, negation, and compound assignments) in all code.

**ResolvedInfo side tables** (on `TypeChecker`, recorded for expressions and calls inside `#verify` functions, for the Lean extractor): `expr_tys` (`span_key(expr span)` / pattern-binding span → type), `call_targets` (call span → `pkg::fn`, `pkg::Type::method`, `Trait::Type::method`, `builtin::...`, `closure::name`), `call_type_args` (generic instantiation), `call_arg_order` (resolved parameter slot → written argument index, `-1` for defaults / implicit `None`), next to `let_infer`, `closure_infer`, `dot_variant_resolve`; `mut_recv_calls` marks `mut self` calls for codegen.


### 3.5 Lean 4 Extraction (`pionc extract-lean`, Pion-LLBC)

`pionc extract-lean` (§5.5) translates the `#verify` closure of a checked workspace into Lean 4 on top of `Aeneas.Std` and the thin `PionLean` library (`lean/`, Lean `v4.36.0-rc2`, Aeneas `1dc8ad31b1`). Ordinary compilation never runs it and gains no syntax for it.

- **Closure.** Every `#verify` function, method and `impl` method (non-`#verify_opaque`) of the extracted packages, plus everything they reach: called `#verify` functions (any package), `#verify impl` dictionaries passed for trait bounds, the structs / enums / traits / constants they mention, and called `#verify_opaque` / `extern "C"` functions (as axioms only).
- **Pion-LLBC** (`compiler/src/core/llbc.pion`): a structured IR built from the AST and the ResolvedInfo side tables. Pure expression trees (literals, variables, wrapping arithmetic, comparisons, field / tuple reads, constructors) and monadic steps (calls, `/ % << >>`, indexing, `?`, `mut` arguments) are separated in strict left-to-right order (a pure operand is copied when a later operand may write it); `for` (C-style, `..` / `..<` / `..=` without computing `end + 1`, `for [i,] x in arr`), `while`, `guard`, `?`, compound assignment, named / default / optional arguments (`call_arg_order`), leading-dot variants, `..base`, tuple destructuring, `is` / `&&` conditions, literal patterns and match guards (falling through to later arms) are desugared into `if` / `match` / `loop` / `break` / `continue` / `return`. Every binding gets a function-unique name and a type; struct / enum / trait names are globally qualified.
- **Lean output per package `pkg`** (module root `Pkg`, `my_pkg` → `MyPkg`; namespace `pkg`): `Pkg/Types.lean` (structs → `structure`, recursive structs / enums → `inductive` (mutually recursive SCCs in `mutual … end`; a recursive struct gets `Name.f` accessors and `Name.set_f` updates), traits → `structure Trait (Self : Type _)` of methods, `#derive(Eq)` and payload-less enums → `deriving BEq` + `Pion.Eq` instance), `Pkg/Funs.lean` (constants, functions, `impl` dictionaries `Type.Insts.Trait`, in dependency order; (mutually) recursive functions are `partial_fixpoint` in `mutual … end`), `Pkg/FunsExternal_Template.lean` (axioms of the external callees, rewritten on every run; definitions that transitively call one are `noncomputable`, everything else stays executable with `#eval`) and `Pkg/FunsExternal.lean` (a copy of the template, written only when absent or still identical to the previously generated template, so a package builds out of the box and a user-edited file is never overwritten). Upstream packages are imported as `Dep.Types` / `Dep.Funs`. Lean keywords are `«»`-escaped; user items named like names the generated code uses (`ok`, `loop`, `Result`, `Option`, …) get a trailing `_`.
- **Types.** `Int` `Std.I32`, `Int64` `Std.I64`, `UInt` `Std.U32`, `UInt64` `Std.U64`, `Byte` `Std.U8`, `Int8` `Std.I8`, `Double` `Pion.Double` (64-bit bit-pattern wrapper), `Bool`, `Char`, `String`, `Unit`, `Option[T]` `Option T`, `Result[T, E]` `Pion.Res T E`, `Array[T]` `Pion.Array T`, `FixedArray[T]` `Pion.FixedArray T`, `ImmArray[T]` `Pion.ImmArray T`, `Bytes` `Pion.Bytes`, `StringBuilder` `Pion.StringBuilder`, `Map[K, V]` `Pion.Map K V`, tuples `A × B × C`; type parameters stay polymorphic (`{T : Type _}`), each bound `T : Tr` is an explicit dictionary parameter `(inst_T_Tr : Tr T)`, and a type parameter compared with `==` or used as a `Map` key gets `[Pion.Eq T]`.
- **Functions.** `def f (a : A) … : Result R`; with `mut` parameters the result is `R × B × C` (`B × C` when `R = Unit`, a single `B` for one) and every exit returns the final values of the `mut` parameters. Mutable state is threaded functionally with fresh SSA names: `x = e` → `let x1 := e`, `s.f.g = e` → nested `{ s with f := { s.f with g := e } }`, `a[i] = e` → `Pion.Array.set`, and a `mut <place>` argument is read before the call and written back field by field afterwards (`mut s.x, mut s.y` update the same `s` in order). Integer `+ - * & | ^` and unary `-` are the wrapping `Pion.I32.add/sub/mul/band/bor/bxor/neg` (per scalar type); `/ % << >>` are `Pion.I32.div/rem/shl/shr`, failing exactly like the native `#verify` checks (`divisionByZero`; `integerOverflow` for `MIN / -1`, `MIN % -1` and a shift amount outside `[0, bits)`); a shift of a non-`Int` left operand by an `Int` count is the mixed `Pion.I64/U32/U64.shl_i32/shr_i32`; comparisons are `Bool` (`Prop` in `if` conditions); `debug_assert(c, …)` is `Pion.debugAssert c`, unreachable code `Pion.panic`.
- **Control flow.** Each loop becomes `f_loopN.body` (`Result (ControlFlow σ σ)` over the loop-carried variables σ, or `ControlFlow σ (Sum R σ)` when it may `return`) and `f_loopN := loop (fun σ => f_loopN.body …) σ` (`Aeneas.Std.loop`); other free variables are parameters. An `if` / `match` whose other branches diverge, or that contains `break` / `continue`, takes the rest of the block into its branches; one that updates outer variables returns them as a tuple (`Sum R σ` with an early `return`) that the rest of the block destructures; one in tail position ends the function itself. The generated `do` blocks use only the subset of Aeneas' `do` elaborator (no early `return`, every `if` has an `else`).
- **Not extractable** (`E_EXTRACT_UNSUPPORTED`, nothing is written): closures and closure calls, string interpolation, `as`, builtins without a `PionLean` model (e.g. `Array::sort`, `String` methods other than `length`, integer bitop methods `rotate_left`/`rotate_right`/`leading_zeros`/`trailing_zeros`/`count_ones`), `Byte` and `Int8` shifts, trait dictionaries inside a recursion cycle. (A loop of a recursive function is emitted as a directly recursive `partial_fixpoint` definition in the function's `mutual` block instead of through `Aeneas.Std.loop`.) `String` and `StringBuilder::to_string` assume valid UTF-8 byte sequences in `#verify` (matching Lean's `String`).

### 3.6 Verified QBE Translation Validation (`tools/qbe_tv`, `tools/qbe_tv_cli`)

`tools/qbe_tv` (`[verify] enabled = true`, extracted to Lean as `QbeTv`) checks that a QBE function after the SSA optimisations refines the function before them; `tools/qbe_tv_cli` (`qbe-tv`) is the untrusted text front end.

- **Subset.** `ir.pion`: integer `w` / `l` values (a `w` value is kept zero-extended), `par`, unary / binary operators with `vendor/qbe/fold.c` semantics (`div` / `udiv` / `rem` / `urem` trap on 0 and on `MIN / -1`), loads / stores of 1 / 2 / 4 / 8 bytes, calls, `alloc`, phis, `jmp` / `jnz` / `ret` / `hlt`. Anything else makes the front end skip the function.
- **Refinement.** Every terminating execution of the source with a result (return value or `hlt`, plus the final world after its loads / stores / calls / allocs) is matched by an execution of the target with the same result. Loads and trapping divisions of the source may be dropped (they do not change the world unless they trap, and a trap is undefined behaviour); every other effect is kept in order with equal operands.
- **Solver vs. checker.** `build_cert` (untrusted) computes a `Cert`: a frozen value graph (`canon.pion`, an append-only hash-consed DAG whose rewrites are exact 32 / 64-bit identities), the symbolic value of every source / target temp, the initialisation certificates (`savail` / `tavail`), the branch facts, the target-to-source block map, and the matched block pairs, each with its replay steps (`MatchEff`, `SkipSrcReadOnly`, `SrcJmp`, `SrcJoin`, `TgtJmp`, `BothJmp`) and its end (`EndRet`, `EndHlt`, `EndJmp`, `EndJnz`, `EndSrcBranch`, `EndTgtBranch`, naming the successor pairs). `verify_cert` re-checks all of it from the two functions alone; `validate_fn(src, tgt) = build_cert` then `verify_cert`.
- **Cost.** No pass is super-linear in the value graph per query: `vg_intern` probes an open-addressing index (`ValGraph.buckets`, rebuilt below load ½; only an accelerator, every hit is compared with `sym_node_eq`), `blk_mentions_table` decides "depends on block b" for every node in one forward sweep (used by `check_avail` once per mapped source block and by `check_facts` once per run of facts of a block), `facts_of` / `fact_in_blk` / `bm_has` binary-search the solver's block-sorted `facts` / `bm_t` (on unsorted input they only find fewer entries), `compute_avail` is one reverse-postorder pass over the dominator tree (Cooper–Harvey–Kennedy), and `compute_facts` keeps at most 16 facts per block (the most recent edge facts first) and prunes until every fact holds on every incoming edge.
- **`qbe-tv --trace <dump>`** validates, for every function of a `qbe -d MG` dump, `After load elimination` directly against `After GCM` (GVN, `simplcfg` and GCM in one step; `Slot coalescing` instead, counted as skipped, when coalescing killed or fused slots). **`qbe-tv --pair <before.ssa> <after.ssa>`** validates the functions of two files by name. Both print `VALIDATED` / `SKIPPED` / `REJECTED <fn>: <reason>` and `validated=N skipped=M rejected=K`; exit 1 when something is rejected, 2 under `--strict` when something is skipped.
- **Gate.** `scripts/test-tv.sh <pionc> <qbe>` (part of `verify-all.sh` [5/6] and `test-linux.sh` [6/6]): the real `qbe -d MG` traces of `tests/tv/opt_suite.pion` and `tests/lean/{codec,algos,captable}` all validate (opt_suite with 0 skipped), the same traces with a `jnz` swapped after GCM are rejected, `tests/tv/good` validate, every `tests/tv/adversarial` miscompilation is rejected, and `tests/tv/qbe_bugs` (reproducers of the `vendor/qbe` bugs B1–B6 that `qbe-tv` + differential fuzzing found: `gvn.c` `dedupjmp` low-32-bit `jnz`, `copy.c` `phicopyref` phi class and `dwl` shift by 32, amd64 `jnz`/`sel` reusing a 64-bit ZF or a shift's ZF, amd64 text-asm shift immediates; and B7–B13 from the Lean-model review: `copy.c` `dwl` keeping a phi's narrowness mark after the assumption it rests on was refuted (now rolled back to the enclosing `and` arm), `gvn.c` `usecls` treating every jump use as 32-bit (a `retl` of the `jnz`-tested temp is 64-bit), `load.c` forwarding a narrow store to a load at a higher offset without masking the bits shifted down from above it, `mem.c` promoting an l-class `loadsw`/`loaduw` of a 4-byte slot to a copy instead of an extension (and not promoting one of an `s` store), `copy.c` `copyref` replacing `=l cnew %w, 0` by the narrower `w` temp, and B13 `phicopyref` replacing an `l` 0/1 phi by the `w` `jnz` argument) give exact results through text assembly and `--obj`, and their trace validates (except B1, whose low-32-bit constant `jnz` fold is beyond `qbe-tv`'s completeness, B13's `l` 0/1 phi over a `w` `jnz` boolean, left unchanged by QBE but beyond `qbe-tv`'s completeness, and B10/B11c/B11d, whose slot rewrites precede the first traced snapshot or use class `s`). `tests/e2e/p100_qbe_soundness` adds the pure-Pion B7 reproducer (dev, `--release`, Wasm32). `scripts/test-lean.sh` extracts `tools/qbe_tv`, builds `QbeTv` and checks the proofs about it: `tests/lean/proofs/QbeTvSem.lean` (exact 32 / 64-bit operator semantics, QBE function semantics, the value-graph denotation, `vg_intern` / `check_vg_dag` / `vid_mentions_blk`), `QbeTvCanon.lean` (soundness of `fits_bits` and of every `canon.pion` rewrite, over any graph `check_vg_dag` accepts) and `QbeTvProofs.lean`.
- **Proof (end to end).** `validate_fn_sound` (and `verify_cert_sound` for any `Cert`) is proved with zero `sorry` / `admit` / `bv_decide` / `native_decide`, and `#print axioms` of it and of every other theorem in `tests/lean/proofs/CheckAxioms.lean` shows only `propext`, `Classical.choice` and `Quot.sound`:
  `validate_fn src tgt = ok true → evalFunc src oracle args w0 fuel = some res → ∃ fuel', evalFunc tgt oracle args w0 fuel' = some res`, for every world type, world oracle, argument list, initial world and fuel. The layers: `QbeTvFacts.lean` (`wf_code`: blocks, an entry block without phis, successors in range and every instruction destination in `[0, ntemps)` (code 16 otherwise); `build_info`, `check_facts`, `check_avail`), `QbeTvReplay.lean` (`check_src_defs` / `check_tgt_defs`, the phi definitions: fold, sole predecessor, select, equal arguments), `QbeTvSim.lean` (the source run against a look-ahead symbolic environment fixed on each block entry), `QbeTvChecks.lean` (views, `match_effect_c`, the skips, `head_ok` / `edge_ok` / `next_ok`, `check_end`, trivial blocks), `QbeTvTgt.lean` (the target invariant and its stability while the source moves inside a pair) and `QbeTvProofs.lean` (one replay step and the replay loop, induction on the source fuel over the pairs, the decomposition of `cert_fail_code = 0`).

## 4. Runtime ABI & Memory Layout (`runtime/pion_rt.h` & `runtime/pion_rt.c`)

**All values passed across QBE IL / C ABI use uniform 64-bit slots (`l` in QBE, `int64_t` in C)** for Shape Polymorphism:
- `Int` (`i32`): sign-extended in 64-bit register (or `w` locally, `l` across generic boundaries).
- `Int64`: `int64_t` (`l`).
- `Double`: IEEE-754 bit-cast (`double` / `d`, boxed to `int64_t` bits in generic slots).
- `Bool` / `Byte` / `Char`: zero-extended in 64-bit slot (`0`/`1`, `0..255`, Unicode scalar `0x0000..=0xD7FF` or `0xE000..=0x10FFFF`); numeric casts `as Char` validate the truncated integer code point and deterministically map any out-of-range, negative, surrogate (`0xD800..=0xDFFF`), or floating-point `NaN`/`±Inf` value to `U+FFFD` (`65533`) on both Native and Wasm32, preserving the zero-extended Unicode scalar ABI invariant across 64-bit slots and compact 4-byte `Char` array/struct storage; `Int8`: sign-extended in 64-bit slot (`-128..127`).
- `Unit`: `0`.
- Non-generic payload-less `enum`s (`UnitEnum`, `pionc-v0.19`): 1-based 64-bit integer (`l` / `int64_t`) in `1..=N` (non-object, no ownership/RC); `Option[UnitEnum]` uses `0` for `None` and `1..=N` for `Some(Vk)` (non-object, no ownership/RC).
- All heap objects (`String`, `Bytes`, `Array`, `Map`, `struct`, generic or payload-carrying `enum`, `Closure`, `Channel`, `Mutex`, `AtomicInt`): `PionObj*` (64-bit pointer, `l` in QBE).

### 4.1 Object Header (24 bytes, 8-byte aligned)
```c
typedef void (*PionDropFn)(void *payload);

typedef struct PionHeader {
    uint32_t owner_tid;        // Thread ID of creator; 0 = FROZEN/SHARED (atomic mode)
    uint32_t local_rc;         // Non-atomic RC used while owner_tid == current_tid
    _Atomic uint32_t shared_rc;// Atomic RC used once owner_tid == 0 (or cross-thread dec)
    uint16_t type_tag;         // PionTag (String=1, Bytes=2, Array=3, Struct=4, Enum=5, Closure=6, Map=7, Channel=8, Mutex=9, Atomic=10)
    uint16_t flags;            // bit 0: FROZEN, bit 1: IMMORTAL, bit 2: SLAB, bit 3: DEEP_FROZEN, bits 4..7: 12-class slab id
    PionDropFn drop_fn;        // Nullable destructor for releasing child pointers
} PionHeader;                  // Total: 24 bytes (clean 8-byte alignment on arm64/x64)
```
Payload immediately follows `PionHeader`: `void* obj = (char*)hdr + sizeof(PionHeader)`.
Header recovery: `PionHeader* hdr = ((PionHeader*)obj) - 1`.

**Immortal static strings** (`.rodata` string literals): `flags = PION_FLAG_IMMORTAL | PION_FLAG_FROZEN`, `owner_tid = 0`. `pion_rc_inc` / `pion_rc_dec` return immediately in 1 branch — **ZERO heap allocation and ZERO `init` code for string literals!**

### 4.1.1 `dyn Trait` Layout (compiler-emitted, no runtime symbols)
- A `dyn Trait` value is one 64-bit pointer (`l`) to a **16-byte fat-pointer box**, an ordinary RC object (`pion_alloc_uninit(16, 4, $pion_drop_dyn)`) whose payload is `{ l data, l vtable }`: `data` is the concrete value in its uniform 64-bit slot (an object pointer, or an `Int`/`Bool`/`Double` bit pattern), `vtable` points to static read-only data.
- One vtable per (trait, concrete type) pair, emitted once per package: `data $pion_vtable_<pair> = align 8 { l is_obj, l freeze_fn, l m0, l m1, ... }` — `is_obj` is `1` when `data` is a heap object, `freeze_fn` the concrete type's recursive freeze routine (or `0`), then one entry per trait method in declaration order. Each entry is a thunk `$pion_dyn_wrap_<pair><member_suffix>(l %self_raw, ...)` that narrows `self` to the concrete ABI type (`w` / `d` / `l`) and calls the impl method. `<pair>` uses `qbe_mangle_pair(Trait, Type)` and `<member_suffix>` uses `qbe_mangle_member_suffix(method)` (`_M<len>_<rev>`): ordinary identifiers such as `Show` and `Point` yield `$pion_vtable_Show__Point` and `$pion_dyn_wrap_Show__Point_M4_show`, while underscore-boundary or qualified names fall back to the prefix-free `0P<len>_<enc>_N<len>_<enc>` encoding so distinct declarations never collide.
- `$pion_drop_dyn(l box)` (box destructor) `pion_rc_dec`s `data` when `is_obj`; `$pion_freeze_dyn(l box)` freezes the box and, through `freeze_fn`, the concrete value, so a `dyn` value stored into a frozen container keeps an atomic RC end to end.
- `Option[dyn Trait]` uses the **null niche**: `None` is the null pointer and `Some(d)` is the box pointer itself (no second allocation, no `$pion_drop_opt_obj` wrapper).
- **Unboxed C-style unit enums (`pionc-v0.19`)**: Every non-generic `enum` whose variants all carry zero payload fields (`variants.length() > 0` and no type parameters) is represented directly as a 1-based 64-bit integer (`l`) in `1..=N` (variant `k` has value `k + 1`, never `0`). It is a non-object value (`is_obj == false`, zero heap allocation, zero static `$pion_enum_*_hdr` data, zero RC, zero `pion_deep_freeze`). `Option[UnitEnum]` preserves the zero-allocation **null niche** (`None = 0`, `Some(Vk) = k + 1`, `is_obj == false`). Unit enums are also hashable scalar keys in `Map[UnitEnum, V]` and composite value-key maps (`Map[(UnitEnum, Int), V]`). Supplying type arguments to a non-generic `enum` (e.g. `Color[Int]`) is rejected at type-checking (`E_TYPE_MISMATCH`).
- **2-variant null-niche enums (`NicheEnum`, `pionc-v0.23`)**: Every `enum` declaration (generic or non-generic) with **exactly 2 variants**, where one variant has 0 fields (`null_tag`) and the other has >=1 fields (`payload_tag`) — decided purely from the `EnumDecl` independent of `type_args`, so erased generic code (`%tp_T`) and monomorphized instantiations always share the exact same runtime layout — encodes the unit variant as `0` (null, zero allocation, zero static object, RC/freeze no-op) and the payload variant as a non-null heap (or static `Bool`) object **without an 8-byte tag word**, placing payload fields starting at byte offset `0` (`payload_offset = 0`, slot indices `0, 1, ...`, e.g. `enum Tree { Leaf; Node(Tree, Tree) }` allocates 16B payload + 24B `PionHeader` = 40B in the 40B slab vs 48B previously). Because `0` is occupied by the unit variant, `Option[NicheEnum]` uses the boxed `Option` representation (`$pion_drop_opt_obj`), keeping `Some(Leaf)` distinct from `None`. Since `pionc-v0.24`, a non-generic niche enum's payload object drops through the canonical slot helper `$pion_drop_slots_<key>` (below) over the payload variant's RC slots, so no tagless `$pion_drop_enum_*` function exists; on Wasm32 those helpers (preserving the `pion_drop_slots_` category prefix in both single-package and multi-package workspace builds) whose reference slots fall within `0..=30` are recognized by P47-A slot-drop mask extraction for iterative zero-`call_indirect` destruction.
- **Canonical drop functions (`pionc-v0.24`)**: the `drop_fn` passed to `pion_alloc`/`pion_alloc_uninit` for a struct or enum object is chosen per allocation site from the declaration's field types (`qbe_is_obj_ty`): (1) a non-generic `struct` whose fields contain RC object slots `S` (slot `k` at byte offset `8k`), and a non-generic niche enum's payload variant with RC slots `S` (at `payload_offset / 8 + k`, i.e. `k`), use `$pion_drop_slots_<key>`, whose suffix lives in one of three disjoint namespaces — the decimal bitmask of `S` for `max(S) <= 30` (parsed by Wasm32 P47-A), `x_<hex>` (zero-padded 16-bit chunks, highest first, at most 32 hex digits) for `31 <= max(S) <= 127`, and `w_<idx>` for `max(S) > 127`, where `idx` is the set's position in the unit's helper table (so no symbol approaches QBE's 1024-byte ELF / Mach-O name limit); de-duplication always uses the full canonical slot set (`qbe_slots_canonical_key`); the helper is a file-local function emitted once per compilation unit and shared by every struct, niche enum and generic instance with the same slot set, which for each slot in ascending order loads the slot and calls `pion_rc_dec` when it is non-null; (2) an object with no RC slot passes `drop_fn = 0`, as does an immutable struct literal whose every RC field is statically null — `Option`-typed and given `Option::None` or an unshadowed bare `None` (a local, parameter, constant or function named `None` is a live value and keeps the drop); (3) a non-generic, non-niche tagged enum passes `0` when no variant has an RC field, and otherwise `$pion_drop_enum_<Name>` (reads the tag, `pion_rc_dec`s the matching variant's RC slots at `8 + 8k`), emitted by the defining unit and `export`ed in `unit_mode` for sibling units (a unit constructing an enum imported from another package emits its own file-local copy under the qualified name); (4) generic structs and enums keep dynamic `%tp_T`-selected slot drops. There is no `$pion_drop_struct_*` symbol. `tests/lean/proofs/WaveAA3Drops.lean` proves the per-type and canonical drops perform the same ordered non-null `pion_rc_dec` sequence, and that a tag-only enum drop is observably equal to a null `drop_fn`.
- The dyn ABI is part of `PION_COMPILER_ABI_REV` `pionc-v0.10` (§6), so objects cached by older compilers are never linked against it.

### 4.2 Required Runtime C ABI Functions (`pion_rt.h`)
All symbols use `pion_` prefix and C calling convention (`arm64_apple` / `amd64_sysv`):

**Memory & Biased RC:**
- `void* pion_alloc(uint32_t payload_size, uint16_t type_tag, PionDropFn drop_fn);`
- `void  pion_rc_inc(void *obj);` (no-op if NULL or `PION_FLAG_IMMORTAL`; non-atomic `local_rc` when `owner_tid == pion_cur_tid()`, non-atomic `shared_rc` on frozen objects while the runtime is in single-threaded mode `g_pion_mt == 0`, else atomic `shared_rc`)
- `void  pion_rc_dec(void *obj);` (no-op if NULL or `PION_FLAG_IMMORTAL`; non-atomic `local_rc` / single-threaded frozen `shared_rc`, atomic in multi-threaded mode; frees + calls `drop_fn` when total RC hits 0)
- `void  pion_enter_mt(void);` (publishes multi-threaded mode `g_pion_mt = 1` / `pion_mt_flag = 1`. - `void  pion_once_call(uint32_t *guard, void (*init_fn)(void));` (thread-safe, same-thread-reentrant one-time initializer used by native module/unit constant init guards; state `0` = uninitialized, `1` = done, `tid + 2` = initializing on that thread; module constant initializers must not spawn another thread that re-enters an exported entry point of the same package while initialization is in progress.)
- `void  pion_rc_freeze(void *obj);` (promotes `owner_tid` to 0 and moves `local_rc` into `shared_rc` before crossing thread boundary; freezing a `Map` also freezes its keys and object values)

*Path contract (every runtime file API below, incl. `pion_fs_mmap_ro` / `pion_fs_write_atomic_bytes`).* A path is the `String`'s UTF-8 bytes. A path that is empty or holds an embedded NUL (`<prefix>\0<suffix>`) is refused while its length is still known — the call fails (`0` / `-1` / `Err` / `ok_out = 0` / empty listing) and never creates, reads, locks, renames or removes `<prefix>`; the `const char *` entries (`pion_fs_mkdir_excl`, `pion_fs_mkdir_excl_status`, `pion_fs_rmdir`, `pion_fs_trylock`, `pion_fs_canon_path`) refuse `NULL`, and Pion code (`pionc`) passes them `pion_fs_cpath(str_data_ptr(path), path.length())`, never a bare `str_data_ptr(path)`. On POSIX the bytes reach the OS unchanged. On Windows every path is converted strictly to UTF-16 (`MultiByteToWideChar(CP_UTF8, MB_ERR_INVALID_CHARS)`; a 512-unit stack buffer, heap beyond) and only wide APIs are used: `_wfopen`, `_wstat64`, `_wmkdir`, `CreateDirectoryW`, `_wrmdir`, `_wchmod`, `GetFileAttributesW` / `GetFileAttributesExW`, `CreateFileW` (lock files and the `FILE_FLAG_OPEN_REPARSE_POINT` nofollow range read, which still rejects reparse points), `FindFirstFileW` / `FindNextFileW`, `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` (rename and the atomic-write replace), `DeleteFileW`; `fs_mkdir_p` starts creating after `X:\` or after a UNC `\\server\share\` prefix (either slash), keeps that prefix's separator, accepts an existing directory as success, and for the share itself (`\\server\share`, with or without the trailing separator) creates nothing and only checks that the server and share names are non-empty and `GetDiskFreeSpaceExW("\\server\share\")` succeeds; `fs_read_range_nofollow` opens the path with `FILE_FLAG_OPEN_REPARSE_POINT` and then checks the opened handle (`GetFileInformationByHandle`: not a directory or reparse point, size equal to `expected_size`), so a junction or symbolic link is refused even for 0 bytes; `pion_fs_write_atomic_bytes` creates its temporary `<path>.piontmp.<pid>.<seq>` with `CreateFileW(CREATE_NEW)` (an existing file of that name is never truncated or removed; the next sequence number is tried, up to 16 names), writes it with `WriteFile` + `FlushFileBuffers`, then `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`, removing only a temporary it created itself; `fs_symlink` always fails (returns `0`) on Windows, while `fs_readlink` resolves reparse points / directory junctions via `GetFinalPathNameByHandleW` (returning the fully resolved absolute final path rather than POSIX's raw link target, and returning `Err` (`EINVAL`) for ordinary files or directories); invalid UTF-8 (bad bytes, overlongs, encoded surrogates, truncated sequences) fails the call and is never replaced by U+FFFD. Directory entries come back through `WideCharToMultiByte(CP_UTF8, WC_ERR_INVALID_CHARS)` and are then sorted by bytes like on POSIX; an entry whose name is not valid UTF-16 (an unpaired surrogate) has no UTF-8 spelling and is omitted. Not yet covered on Windows (still ANSI / code-page dependent): process `argv` (`GetCommandLineW`), subprocesses (`CreateProcessW` for `proc_exec*`), environment variables (`_wgetenv`), the console code page, and `\\?\` paths longer than `MAX_PATH` (260).

**FFI raw pointers, C callbacks, C variadic calls & zero-copy helpers (no `World`; compiler builtins → direct/inline QBE IR):**
- `extern "C" fn name(fixed_params..., ..., vararg_params...) -> Ret [= "c_sym"]`: native C variadic ABI support. At least one fixed parameter is required before `...` (duplicate or leading `...` is a syntax error); trailing typed vararg parameters stay statically type-checked at call sites (or 0 trailing parameters, e.g. `fn foo(a : Int, ...) -> Int`). Emits QBE variadic calls `call $c_sym(fixed..., ..., varargs...)` with C default argument promotions (`Int`/`Bool`/`Byte` as `w`, `Int64`/`Ptr` as `l`, `Double` as `d`), satisfying Apple Silicon ARM64 Darwin PCS (all variadic args passed on the stack) and Linux x86_64 SysV ABI (register allocation + `%al` XMM count).
- `[pub] extern "C" fn name(p1 : T1, ...) -> Ret [= "c_sym"] { ... }`: exports a Pion function with C ABI under `$c_sym` (non-variadic; `Int`/`Bool`/`Byte`/`Char` as `w`, `Double` as `d`, `Int64`/`Ptr`/`UnitEnum` (`1..=N`, non-owned/no-RC)/`Option[UnitEnum]` (`0` = `None`, `1..=N` = `Some(Vk)`, non-owned/no-RC)/`String`/`Bytes`/heap objects as `l`, `Unit` as void). Incoming parameters use borrowed semantics (`is_owned = false`, no RC change on entry/exit); returned heap objects transfer ownership (`RC=1`) to the C caller (non-object `UnitEnum` and `Option[UnitEnum]` values carry no RC/ownership). `c_fn_ptr(target) -> Ptr` returns the C function pointer (`%t =l copy $<c_sym>`) for any in-scope `extern "C" fn` (or imported `pub extern "C" fn`).
- Zero-copy data pointers (inline QBE IR, 0 runtime bytes): `str_data_ptr(s : String) -> Ptr` (`s + 8`, NUL-terminated UTF-8), `bytes_data_ptr(b : Bytes) -> Ptr` (`*(b + 16)`), `array_data_ptr(a : Array[T] | FixedArray[T]) -> Ptr` (`*(a + 24)`), and `fixed_array_data_ptr(a : FixedArray[T]) -> Ptr` (`*(a + 24)`, contiguous slots: 1-byte compact slots for `Bool`/`Byte`/`Int8`, 4-byte compact slots for `Int`/`UInt`/`Char`/`Float`, flat inline POD slots for small POD structs, and 64-bit slots otherwise).
  - **Static temporary-argument guard (`E_TEMP_DATA_PTR`) & slot pinning**: arguments to `*_data_ptr` must be a local variable or parameter, a recursive field-access chain rooted at one (e.g. `x.a.b`), an immortal string literal (for `str_data_ptr`), or a package/imported global constant. Passing any temporary expression (concatenation `a + b`, `make().field`, function call return value, array index `arr[i]`, string interpolation) is a compile-time error (`E_TEMP_DATA_PTR`, with a fix-it to bind to a local variable first). When a local binding's slot is passed (directly or via a field chain) to `*_data_ptr` anywhere in its lexical scope (including nested blocks, branches, loops, and expressions, respecting inner-scope shadowing), codegen pins that binding slot through the end of its owning scope, excluding it from Perceus-lite last-use early drop and move-out optimizations.
  - **Remaining caller responsibilities**: `*_data_ptr` returns an untracked raw `Ptr`; callers must not use the pointer after (1) `Array::push`/reallocation on the backing array, (2) reassigning the owning local or replacing a mutable field along the chain, or (3) escaping the pointer past the owning binding's lexical scope.

### 4.3 Profiler Runtime (`runtime/pion_prof.h`, `runtime/pion_prof.c` → `libpionrt_prof.a`)

The profiler is a **separate runtime archive**: `libpionrt_prof.a` = `pion_rt.c` compiled with `-DPION_PROF=1 -fno-omit-frame-pointer` + `pion_prof.c` (and `libpionrt_cli_prof.a` for `pionc` itself). Every hook in `pion_rt.c` sits under `#ifdef PION_PROF`, so the default `libpionrt.a` gains **0 bytes**, stays under the `65,536 B` budget, and default `pionc build|run|test` output is bit-for-bit unchanged. Bootstrap/gate scripts prebuild `out/libpionrt_prof.a` and `out/libpionrt_cli_prof.a`.

- **Mode bitmask `prof_mask`** (shared by Native, Wasm32, CAS keys and the CLI): `PION_PROF_NONE = 0`, `PION_PROF_CPU = 1`, `PION_PROF_ALLOC = 2`, `PION_PROF_RC = 4`, `PION_PROF_ALL = 7`. `uint32_t pion_prof_build_modes` (default `PION_PROF_ALL`) records the compiled capabilities; a binary built with inline RC cannot see every RC operation (`rc_partial`, §5.9).
- **Public API**: `void pion_prof_anchor(void)` (address anchor for load-slide computation), `pion_prof_init`, `pion_prof_flush`, `pion_prof_pause`, `pion_prof_resume`, `pion_prof_reset`, `pion_prof_thread_init`. Internal hooks (`pion_prof_on_alloc`, `pion_prof_on_retire`, `pion_prof_on_backing_alloc|free|realloc`, `pion_prof_on_reserved_add|sub`, `pion_prof_on_rc_inc|dec|destroy|freeze`) are called only from `pion_rt.c`. The raw profile is flushed at `atexit` and right before `abort()` in a panic.
- **Environment** (read once by `pion_prof_init`, then `unsetenv`'d unless `PION_PROF_INHERIT=1`, so child processes never clobber the parent's output):
  - `PION_PROF_OUT=<path>` — enables profiling; raw profile written via temp file + atomic rename.
  - `PION_PROF_MODES=<1..7>` — requested modes (Native default `3` = `cpu,alloc`; `pionc` always sets it explicitly).
  - `PION_PROF_HZ=<10..10000>` — `ITIMER_PROF` frequency (default `997`).
  - `PION_PROF_SAMPLE_RATE=<N>` (`N >= 1`) — deterministic 1-in-N **stack** sampling for alloc/RC events (default `1` on Native, `64` on Wasm32). Per-type-tag and per-domain totals are always exact regardless of `N`.
  - `PION_PROF_RETAINED=0|1` — track live objects for exact `inuse` stacks and peak-live attribution (default `0`).
  - `PION_PROF_INHERIT=0|1` — keep the variables for child processes (default `0`).
- **CPU sampling is PC-only on Native (`cpu_stack_mode: "pc_only"`)**: the `SIGPROF` handler reads only the interrupted PC (arm64 PAC stripped) and bumps a static lock-free 65,536-slot open-addressing table (linear probe ≤ 32, overflow counted in `dropped_cpu`); it never walks the stack, allocates, locks or touches TLS. Consequently Native reports self time only (`cum_cpu_pct: null`). Wasm32 CPU profiles come from `node --cpu-prof` and carry full stacks (`cpu_stack_mode: "full"`).
- **Exact accounting domains** (non-overlapping): `managed` (RC objects: one alloc hook on successful allocation, one retire hook in `pion_destroy` after `drop` and before the slot is reused), `backing` (raw buffers: slab raw alloc/free and the `realloc` branches of array/string-builder growth, attributed by synchronous caller frame such as `pion_arr_grow`, `pion_map_grow`, `pion_strbuf_grow`; read-only `mmap` `Bytes` excluded), `reserved` (OS memory held by the allocator: slab chunks, medium cache, large objects → `reserved_bytes` / `peak_reserved_bytes`), and `rc` (`rc_inc`, `rc_dec`, `rc_atomic_inc`, `rc_atomic_dec`, `rc_destroy`, `rc_immortal` per type tag). Alloc/RC stacks are captured synchronously (outside signal context) by a frame-pointer walk validated against the thread's real stack bounds; unknown bounds yield an empty stack, never a guessed one.
- **Wasm32**: `runtime/pion_wasm_rt.mjs` enables alloc/RC/retained profiling only when `PION_PROF_OUT` is set (zero overhead otherwise), maps `wasm-function[N]` frames through the module's `name` section, and writes the same `PIONPROF 1` raw format (§5.9). The compiler side is `emit_wasm_from_ssa_units_prof(units, emit_names, prof_mask, on_stage)` (`prof_mask = 0` is identical to `emit_wasm_from_ssa_units_opts`): any non-zero mask forces the `name` section; `PROF_ALLOC` routes every allocating/freeing helper through `pion_rt.*` imports instead of in-module fast paths; `PROF_RC` does the same for `pion_rc_inc` / `pion_rc_dec`. `PION_WASM_RT_ABI` stays `2`.

### 5.1 `pionc check --json <path>`
```json
{
  "ok": false,
  "diagnostics": [
    {
      "file": "src/app.pion",
      "line": 12,
      "col": 5,
      "code": "E_NOT_SEND",
      "message": "cannot capture mutable non-Send value `counter` inside `spawn`",
      "expected": "Send",
      "found": "MutBox",
      "fixit": "wrap `counter` in `Mutex::new(...)` or `AtomicInt::new(...)`"
    }
  ]
}
```
- `edits` (optional, emitted only when non-empty): source patches `[{"file","line","col","end_line","end_col","replacement","applicability"}]` replacing the 1-based range `[line:col, end_line:end_col)` (end exclusive, columns in bytes; an empty range is an insertion). `applicability` is `"machine"` (deterministic, safe to apply blindly without placeholders or follow-up edits) or `"maybe"` (inserts placeholders such as `panic("todo")`/`0`, wraps a binding in `Mutex::new(...)`, or requires follow-up edits at other sites). Edits of one diagnostic never overlap: apply them from the last offset to the first. Each distinct edit is attached once. All 12 agent error classes of `benchmarks/agent_eval` carry one:
  - `E_TYPE_MISMATCH` (return type, `"machine"`) — a function body whose type contradicts the declared return type: rewrites the declared return type to the body's type.
  - `E_TYPE_MISMATCH` (arity, `"maybe"`) — too many arguments: deletes the extra ones; too few: appends a type-default placeholder for each missing parameter (`0`, `""`, `false`, ...).
  - `E_TYPE_MISMATCH` (unknown field, `"machine"`) — replaces a misspelt field with the closest declared field when it is unique and within Levenshtein distance 2.
  - `E_NON_EXHAUSTIVE` (`"maybe"`) — inserts the missing `match` arms (`panic`-bodied) before the first arm.
  - `E_PRIVATE_SYMBOL` (`"machine"`) — inserts `pub ` at the target declaration.
  - `E_TRAIT_NOT_IMPLEMENTED` (`"maybe"`) — appends an `impl Trait for Type { ... }` skeleton (every trait method with its signature, `panic("todo")` bodies) after the type's declaration (generic bounds and `dyn Trait` conversions).
  - `E_TRAIT_METHOD_SIGNATURE` (`"machine"`) — rewrites the impl method's return type to the trait's.
  - `E_NOT_SEND` (`"maybe"`) — a captured non-`Send` local: wraps its declaration in `Mutex::new(...)` (and its type annotation in `Mutex[...]`), or prefixes the capture with `move` where ownership transfer fits. Uses of the binding inside the closure are left as they are and may need a second step (e.g. `with_lock`).
  - `E_UNHANDLED_RESULT` (`"machine"`) — prefixes the discarded statement with `let _ = `.
  - `E_CAPABILITY_MISSING` (`"maybe"`) — inserts `world : World` as the first parameter of the enclosing function; its call sites then report the arity and need a second step passing `world`.
  - `E_NO_IO_VIOLATION` — emitted (with no `edits`) when a `#no_io` / `#render_thread` function, `impl` method, or nested closure accepts/references `World` or calls any `World`-gated IO builtin, runtime primitive, or `scope`.
  - `E_GUARD_ELSE_NOT_DIVERGE` — emitted (with advisory `fixit`, no semantic-changing `edits`) when a `guard ... else { ... }` block can fall through without diverging.
  - `E_CONST_CYCLE` — emitted when top-level `let` initializers in a package form a dependency cycle (directly or through same-package direct function calls), reporting the full cycle path.
  - `E_MISSING_TYPE` (`"machine"`) — inserts the inferred return type (`-> T`) (no edit for an uninferable empty `let` collection: the fix-it names the annotation to add).
  - `E_TYPE_MISMATCH` "cannot assign to immutable variable" (`"machine"`) — `let x` → `let mut x` at the declaration (also for an immutable root passed as `mut <place>`); a plain identifier passed to a `mut` parameter gets a `mut ` insertion (`"machine"`).
  - `E_VERIFY_UNSUPPORTED`, `E_VERIFY_MOVE`, `E_VERIFY_BORROW_ESCAPE`, `E_VERIFY_MUT_ESCAPE`, `E_VERIFY_ALIASING`, `E_VERIFY_CLOSURE_CAPTURE`, `E_VERIFY_UNVERIFIED_CALLEE` — `mut` / `#verify` rules of §3.4 (fix-its, no `edits`).
  - `E_BENCH_LOOP_CONTEXT`, `E_BENCH_LOOP_DUPLICATE`, `E_BENCH_LOOP_CONTROL_FLOW` — `bench` / `bench_loop` rules of §3.2 (fix-its, no `edits`).
  - Cross-language agent habit diagnostics (zero false positives on valid Pion, Pion-JSX, `<`/`>` comparisons, bitwise `&`, `match` `=>`, and supported `#[...]` attributes):
    - `E_HABIT_ANGLE_GENERICS` — `<T>` generics in `fn`/`struct`/`enum` type parameter lists or type arguments (`Vec<Int>`, `Option<Int>`); attaches `"machine"` edits replacing `<...>` with `[...]` on clear single-line forms.
    - `E_HABIT_RUST_REF` — Rust-style `&mut x` (`"machine"` edit → `mut x`), `&x` (`"maybe"` edit → `x`), or `&T`/`&mut T` in type position.
    - `E_HABIT_RUST_ATTR` — unsupported Rust-style `#[...]` attributes (while keeping `#derive(Eq)`/`#[derive(...)]`, `#no_io`/`#[no_io]`, `#render_thread`/`#[render_thread]`, `#verify`/`#[verify]`/`#![verify]`, `#verify_opaque`/`#[verify_opaque]`).
    - `E_HABIT_JS_CONST` — `const x = ...` at top level or statement position (`"machine"` edit `const` → `let`).
    - `E_HABIT_JS_FUNCTION` — `function foo(...)` or `function(...) { ... }` (`"machine"` edit `function` → `fn`).
    - `E_HABIT_STRICT_EQ` — `===` / `!==` (`"machine"` edit → `==` / `!=`).
    - `E_HABIT_ARROW_FN` — `(...) => { ... }` / `(...) => expr` / `x => { ... }` outside `match` and JSX (`"machine"` edits on `(...) => { ... }`).
    - `E_HABIT_MOONBIT_PKG` — MoonBit `@pkg.name` (`"machine"` edit → `pkg::name`).
  - See `docs/diagnostics.md` for executable `before`/`after` examples of every core and `E_HABIT_*` diagnostic code (automatically verified by `compiler/src/core/diagnostics_doc_test.pion`).

### 5.3 `pionc test [--json] [--target <t>] [--package <name>|-p <name>] [--deps|--no-deps|--only-pkg] [--filter <substr>] [--jobs <n>] [--isolate] <path>`
- Runs all `test "name" { ... }` blocks (active `debug_assert`). By default, native tests within a package execute in deterministic batches of up to 16 tests (`bin -2 <token> -1` for a full package with `<= 16` tests, a single explicit batch for a filtered subset with `2 <= N <= 16` tests, or `ceil(N / 16)` interleaved batches `i % ceil(N / 16)` for `N > 16`), independent of `--jobs` so batch boundaries and `--json` output stay byte-for-byte identical for any `--jobs`. Tests within the same batch share process state; each batch verifies a per-invocation completion token printed only upon reaching `@done`. If any batch exits non-zero (panic, assertion failure, crash, or non-zero exit) or exits `0` early without emitting its completion token (e.g. a test calling `exit(0)` / `_Exit(0)`), its partial stdout is discarded and that batch falls back deterministically: batches with `<= 4` tests go directly to isolated single-test child processes (`bin <idx>`), while larger batches (`> 4` tests) bisect at the midpoint (`count / 2`) in parallel (passing halves are accepted without re-running; if both halves of a parent fail, bisection circuit-breaks straight to isolated fallback for both halves; otherwise only the failing half continues bisecting until `<= 4` tests before isolated replay) so per-test pass/fail status and stdout remain exact (stderr emitted by a failing test may repeat up to 4 times across `16 -> 8 -> 4 -> isolated` replay, and a batch failure caused purely by cross-test state interference reports each sub-batch / single test's true passing result after bisection or isolated replay, consistent with existing isolated fallback semantics). Passing `--isolate` or setting `PION_TEST_ISOLATE=1` forces strict per-test isolated child processes from the start.
- **Target execution (`--target <t>` / `$PION_TARGET`)**: the real host target is detected from OS / `uname -sm` independently of `$PION_TARGET`. If the active test target equals the host target, tests compile and run natively; if the active test target is `wasm32`, tests compile to a Wasm32 test module and execute via `node runtime/pion_wasm_rt.mjs <wasm> <idx>` using the same `pionc test` protocol; any other cross-platform target (whether requested by `--target` or `$PION_TARGET`) is explicitly refused with a non-zero exit code (and a single JSON document `{"ok":false,"error":"..."}` under `--json`). `pionc check`, `pionc query`, and `pionc doc` also accept `--target <t>` (defaulting to the host target) to evaluate `[targets]` file filters for that target; `pionc fmt` always formats all `.pion` files regardless of `[targets]`.
- **Default package selection**:
  - Single package target (a directory with `pion.toml` that is not a `[workspace]` root): defaults to testing only that package itself (`--no-deps` behavior); local `path` dependencies are built/checked as needed but their own `test` blocks are skipped unless `--deps` is passed. `--no-deps` and `--only-pkg` remain accepted as explicit aliases.
  - `[workspace]` root target: defaults to testing all workspace members (hybrid roots include themselves); local `path` dependencies outside the workspace are skipped unless `--deps` is passed.
  - `--deps` recursively tests every local `path` dependency in the resolved graph (packages from the git cache are always excluded). `--package <name>` / `-p <name>` restricts testing to a single named package and is mutually exclusive with `--deps` / `--no-deps`.
- One pass over the workspace: the package graph is loaded, CAS-built and interface-checked once; packages without (matching) tests stop after type checking. Each selected package first probes a source-level test metadata cache `$PION_CACHE_DIR/testmeta/<test_src_key>.tsv` (indexed as `testmeta:<test_src_key>.tsv`), where `test_src_key` (`testsrc_v2`) hashes `compiler_fp`, `qbe_target`, `qbe_macos_ver`, package name, normalized `pkg_root`/`pkg_cwd`, relative package + `*_test.pion` paths and source content SHA-256s (from the single loaded in-memory snapshot), transitive upstream `.pionsig`/`.pionstub` hashes, dependency aliases, all linked dependency object keys/content fingerprints, link options, and effective link context — intentionally excluding `--filter` so different `--filter` runs share one cached `testmeta` + `testbin` entry. A `testmeta` entry stores `NONE` for 0-test packages or `<bkey_file>` followed by the escaped full test-name list; on `testmeta` HIT (jointly pinned and verified with `testbin:<bkey_file>` when non-`NONE`), frontend `check`, `emit`, and SSA cleanup are skipped completely and the cached test binary runs through the same deterministic 16-test interleaved batched / `--isolate` runner. On miss, each tested package's test object is cached under `$PION_CACHE_DIR/testbin/` keyed by `sha256(compiler_fp | testobj_v2 | target | sha256(test SSA))` (with generated test SSA streamed directly to a temporary file and cleaned up after compilation), and its linked test binary by that object key plus every linked dependency object's pure-content identity (explicit CAS `dep_obj_keys` + byte size for CAS-produced `.o`s, streaming `pion_cli_sha256_file` for external objects — zero `mtime`) and the link libraries — a dependency whose body or upstream interface changed has a new CAS key, so a stale binary is never reused. `testmeta` is written only after `check` succeeds with zero diagnostics and (when tests exist) `testbin` compiles and links cleanly. Both `testbin/` and `testmeta/` entries are LRU-tracked in `index.tsv` and evicted with the rest of the CAS.
- Multi-package frontend `check+emit`, C stub compilation (`c_sources`, keyed by package name + normalized source path so same-named stubs never collide and link order stays deterministic; both `pionc build` and `pionc test` compile workspace `c_sources` misses in parallel bounded by `--jobs <n>`), missing test binary compilation/linking, and isolated per-test child-process execution all run in parallel bounded by `--jobs <n>` OS threads (default `$PION_JOBS`, else capped at host CPU count (max 16)); results are reported in deterministic package order, then test order, so `--json` output is byte-for-byte identical for any `--jobs`. `PION_CAS_TRACE=1` prints per-phase `[test]` timings on stderr.
- Single-file JSON output: `{"ok":bool,"passed":N,"failed":M,"tests":[{"name":"...","ok":bool}]}`
- Package / workspace JSON output: `{"ok":bool,"total":N,"passed":N,"failed":M,"deps_skipped":K,"packages":["..."],"tests":[{"pkg":"...","name":"...","ok":bool}]}` where `deps_skipped` counts skipped local `path` dependency packages (excluding git-cached packages; `0` under `--deps` or `--package`). In human-readable mode, when `deps_skipped > 0`, a trailing line `note: skipped K local path dependency package(s); pass --deps to also test them` is printed.
- JSON error contract: under `--json`, stdout is always a single valid JSON document with non-zero exit code on failure — infrastructure, argument, manifest, `--package`, build/QBE/C-stub/link, and runner errors emit `{"ok":false,"error":"..."}` (or compiler diagnostic JSON `{"ok":false,"diagnostics":[...]}`), never empty stdout and never partial test output followed by an error document.
- Built-in constructors `StringBuilder::new()`, `Map::new()`, `Array::new()` require 0 arguments; `Bytes::new([len])` and `Channel::new([cap])` take 0 or 1 positional `Int` argument; `Mutex::new(v)` takes 1 positional argument; `AtomicInt::new(v)`, `StringBuilder::with_capacity(cap)`, `Map::with_capacity(cap)`, and `Array::with_capacity(cap)` take 1 positional `Int` argument. Arity violations report `E_ARITY_MISMATCH` and named arguments are rejected (`E_TYPE_MISMATCH`).
- Additional diagnostic codes:
  - `E_PRIVATE_SYMBOL`: accessing a non-`pub` function, struct, enum, method, or constant from an imported package.
  - `E_IMPORT_CYCLE`: cyclic package dependency detected across `pion.toml` manifests.
  - `E_UNKNOWN_PACKAGE`: importing or depending on an undeclared package.
  - `E_DUPLICATE_C_SYMBOL`: two `extern "C" fn ... { ... }` definitions across packages export the same C symbol name.

### 5.5 `pionc extract-lean --out <dir> [--pkg <name>] [--json] [<path>]`
- `<path>`: a file, a package directory or a workspace root (default `.` when it has `pion.toml` / `src/`); `--out` is required (exit 1 otherwise). `--pkg <name>` extracts only the closure of that package (and the items of its dependencies it reaches).

### 5.6 `pionc lint [--fix] [--locked] [--offline] [--target <target>] [--json] [input1 ...]`
- Built-in independent linter enforcing 7 mandatory, zero-configuration `L_*` rules (no `pion.toml` `[lint]` toggles, no `--disable`/`--allow`/`--max-*` flags, no inline `#allow(...)` suppressions).
- **Target & package selection**:
  - Single file, flat file list, or directory without `pion.toml`: loads and lints the given files directly (same as `pionc check`).
  - No positional target: defaults to `"."` when `pion.toml` or `src/` exists.
  - Manifest root (single package or `[workspace]`): loads the dependency graph with `--locked`/`--offline`/`--target` in lockfile read-only mode (neither `pionc lint` nor `pionc lint --fix` ever creates or modifies `pion.lock`), then selects packages strictly by `--no-deps` canonical directory semantics (virtual workspace → expanded `members`; hybrid workspace → root + `members`; single package → that package only). External git/registry dependencies and non-member `../path` dependencies are never linted or modified by `--fix`.
  - Selected packages always type-check real bodies on the exact same file set as `pionc check` / `pionc test` (never skipped via `.pionsig`). Production sources are checked first; if any `E_*` diagnostic occurs anywhere in the graph or selected package (production or `*_test.pion`), `pionc lint` prints the `E_*` diagnostics and exits `1` without running lint or writing disk.
  - Semantic lint rules and `--fix` edits apply strictly to active files physically owned by the selected package for the selected `--target`. Inactive `[targets]` `.pion` files in the selected package are only scanned to protect active `L_UNUSED_IMPORT` declarations from unsafe deletion (the diagnostic `fixit` names the inactive file and advises `pionc lint --target <target>`) and to enforce physical line limits (`L_FILE_TOO_LONG`); inactive target files are never rewritten cross-target. When a selected package (or any transitive dependency it loads) declares non-empty `[targets]` rules, `L_IMPLICIT_IMPORT` and `L_UNUSED_IMPORT` retain their diagnostics and `fixit` hints with no `"machine"` edits, and `L_UNUSED_MUT` conservatively treats any `let mut` binding used as a method-call receiver as needing mutability so single-target `--fix` never breaks another target's imports or `mut self` receivers.
  - Physical line counts (`L_FILE_TOO_LONG`) and `--fix` edit offsets are always computed against the original on-disk file text (never counting `#![verify]` injected by `[verify] enabled = true`).
- **Output & exit code**:
  - Default / `--json`: `{"ok":bool,"diagnostics":[...]}` (sorted deterministically by `(file, line, col, code, message)` and deduplicated; `edits` are stripped for non-committable targets such as symlinks).
  - `--fix`: `{"ok":bool,"fixed":N,"files":[...],"diagnostics":[...]}` (on load/argument/commit failure under `--json`: `{"ok":false,"error":"...","fixed":0,"files":[],"diagnostics":[]}`).
  - Exit code is `0` iff `diagnostics` is empty, otherwise `1`.
- **Transactional `--fix`**: collects only `L_*` edits with `applicability == "machine"` targeting non-symlink regular files physically owned by a selected package directory, accumulates non-overlapping edits in memory across up to 3 rounds with full production + test verification on every round, aborts with 0 disk writes (`fixed: 0, files: []`) if any round produces `E_*` or detects read-set drift across rounds, acquires the CAS-directory exclusive commit lock (`$PION_CACHE_DIR/lint-fix.lock`, failing closed if the lock cannot be acquired), verifies the full read set (selected files, manifests, `pion.lock`, loaded dependencies, load-time directory snapshots including nested `src/pion.toml` / `tests/pion.toml` presence, and per-file package ownership re-checked under the lock) is unchanged on disk before committing atomically, and checks rollback results on partial failure. Re-running `--fix` on a clean/fixed package is strictly idempotent (`fixed: 0`).
- **Mandatory `L_*` diagnostic codes**:
  - `L_IMPLICIT_IMPORT` (`"machine"` edit when unambiguous across the package): file uses an external package alias `alias::` without declaring `import` for it in that file.
  - `L_UNUSED_IMPORT` (`"machine"` edit when no other file in the package implicitly depends on the alias and the import occupies its own clean line): declared `import` is unused in this file or duplicated in the same file.
  - `L_UNUSED_LOCAL` (`"machine"` edit renaming single `SLet` `name` → `_name` only when `_name` does not appear anywhere in the enclosing top-level declaration or package-level `consts`/`fns`): local binding (`SLet`, `SLetTuple`, `SForRange`, `SForIn`, `match`/`is` `PIdent`) is never referenced; `_`-prefixed names and all parameters are exempt.
  - `L_UNUSED_MUT` (`"machine"` edit deleting `"mut "`): local `let mut` binding is never reassigned, passed as `mut <place>`, or used as receiver of a `mut self` method.
  - `L_UNREACHABLE_CODE` (no edit): statement following a statically diverging statement (`return`, `break`, `continue`, `TNever`/`never_calls` expression, all-diverging `if`/`match`, or diverging block); reported once per unreachable run. Loops (`while`/`for`) and `guard` are never treated as unconditionally diverging.
  - `L_SELF_ASSIGN` (no edit): `lhs = rhs` where both sides are syntactically identical pure `EIdent`/`EField` chains (`x = x`, `self.pos = self.pos`); excludes compound assignment, indexing, and calls.
  - `L_FILE_TOO_LONG` (no edit): original on-disk `.pion` file exceeds `10000` physical lines (reported at `10001:1`).
  - Executable `before`/`after` examples for all 7 `L_*` codes live in `docs/diagnostics.md` and are verified by `compiler/src/core/diagnostics_doc_test.pion`.

### 5.7 `pionc check --server [--target <t>] [--locked] [--offline] [--include-tests] [--package <name>] <target>`
- Long-lived JSON-Lines (NDJSON) checking server for high-frequency agent iteration over a single root package (virtual workspaces require `--package <name>`). Keeps upstream dependencies (`ImportedPkg`s loaded from CAS `.pionsig`/`.pionstub` or source) warm in memory across requests; each check request is a **stateless** overlay over the baseline snapshot and never mutates the baseline.
- **Framing & limits**:
  - Reads one UTF-8 JSON line per request from `stdin`, hard-capped at **64 MiB** (`67,108,864` bytes) during reading via compiler-only `runtime/pion_cli.c` (`libpionrt.a` unchanged). An oversized line stops buffering immediately, drains through `\n`/EOF, emits `{"ok":false,"protocol_error":"request exceeds 64 MiB limit","diagnostics":[]}`, and continues to the next frame.
  - Blank/whitespace-only lines are ignored. Clean EOF exits `0`; stdin I/O read errors print to stderr and exit `1`. Each response is written in a single `fwrite` + `'\n'` + single `fflush(stdout)`.
- **Request fields** (strict JSON object; duplicate keys anywhere in a request are rejected; `"id"`, when present, must be a JSON scalar and is echoed verbatim preserving big-integer spelling; unknown fields or mixing `"quit"`/`"reload"` with check fields return `"protocol_error"`):
  - `{"id": ..., "files": {"src/main.pion": "..."}, "removed": ["src/old.pion"], "full_replace": false, "include_tests": false, "include_types": false, "filter_files": ["src/main.pion"]}`:
    - All paths in `files`, `removed`, and `filter_files` must be root-relative `.pion` paths with `/` separators (no `\`, NUL, leading/trailing `/`, empty segments, `.`/`..`, drive prefixes, duplicates, case-insensitive collisions within or across `files`/`removed`/`filter_files` and active paths on all platforms, or `files`/`removed` overlap; `removed` paths must exist in the baseline).
    - `filter_files` is 3-state when `include_types: true`: omitted = all root files, `[]` = zero files, `[...]` = only listed root-relative files.
    - Response: `{"id": ..., "ok": bool, "diagnostics": [...], "types": [...]}` (`"types"` included iff `include_types: true`, same schema as `query types` `files`).
  - `{"id": ..., "reload": true}`: atomically rebuilds the workspace/upstream/baseline snapshot from disk; swaps only on success (`{"id": ..., "ok": <upstream_diags==0>, "reloaded": true, "diagnostics": [...]}`), retaining the previous snapshot intact on fatal load failure (`protocol_error`).
  - `{"id": ..., "quit": true}`: emits `{"id": ..., "ok": true, "quit": true}` and exits `0`.

### 5.8 `pionc bench [--json] [--package|-p <name>] [--filter <substr>] [--target <t>] [--iters <N>] [--samples <K>] [--warmup-ms <ms>] [--time-ms <ms>] [--save <path>] [--compare <base.json>] [--profile[=cpu|alloc|rc|all]] [--profile-out <path>] [--sample-rate <N>] [--profile-hz <Hz>] [--retained] [path]`
- Compiles every selected `bench "name" { ... }` block (§3.2) into one bench runner per package (always `--release` codegen, regular `libpionrt.a`, **zero** profiler instrumentation unless `--profile` is given) and measures it. Supported on every host target, including `--target wasm32` (run via `node`).
- **Flags**:
  - `--package|-p <name>` selects one workspace member; `--filter <substr>` selects benches whose name contains `<substr>`.
  - `--iters <N>` fixes the iteration count per sample (otherwise auto-calibrated so one sample takes at least `max(10 ms, time_ms / K)`); `--samples <K>` sets the number of measured samples (default `7`); `--time-ms <ms>` is the total measurement budget used by calibration (default `500`); `--warmup-ms <ms>` sets the warmup (default `50`, or `0` when `--iters` is given).
  - **CI and tests MUST pass `--iters 1 --samples 1`** (a smoke run: deterministic, no calibration, no timing assertions).
  - `--save <path>` writes the JSON result to `<path>` (a baseline for a later `--compare`).
  - `--compare <base.json>` compares the current run with a saved baseline (below).
  - `--profile[=...]`, `--profile-out <path>`, `--sample-rate <N>`, `--profile-hz <Hz>`, `--retained`: profile the benches instead of timing them cleanly (below; same semantics as §5.9).
- **Result JSON** (`--json`, and the `--save` file), `schema_version: 1`:
  ```json
  {"schema_version":1,
   "machine_fp":{"target":"amd64_sysv","cpu_count":16,"pionc_id":"..."},
   "benchmarks":[{"name":"parse_small","iters":120000,"samples":7,
     "median_ns":812.4,"min_ns":801.0,"max_ns":845.2,"p95_ns":840.1,"mad_ns":4.3,"cv_pct":1.6,
     "ops_per_sec":1230921.0,"samples_us":[97,98,97,99,97,101,98]}]}
  ```
  - `*_ns` are nanoseconds **per iteration** (median/min/max/95th percentile/median absolute deviation over the `K` samples); `cv_pct` is the coefficient of variation; `samples_us[]` are the raw per-sample wall times in microseconds for `iters` iterations each.
  - `machine_fp` identifies the measuring environment (`target`, `cpu_count`, `pionc_id`); numbers from different fingerprints are not comparable.
- **`--compare <base.json>`**: reports **every** benchmark (matched by `name`) against the saved baseline:
  ```json
  {"schema_version":1,"incomparable":false,
   "machine_fp":{"target":"amd64_sysv","cpu_count":16,"pionc_id":"..."},
   "comparisons":[{"name":"parse_small","status":"improved","base_median_ns":812.4,"patched_median_ns":640.2,"delta_ns":-172.2,"delta_pct":-21.2},
                  {"name":"new_case","status":"added","base_median_ns":null,"patched_median_ns":95.0,"delta_ns":null,"delta_pct":null}]}
  ```
  - `status` is `improved` when `delta_pct <= -3.0`, `regressed` when `delta_pct >= 3.0`, otherwise `noise`; `added` (only in the current run) and `removed` (only in the baseline) carry `null` for the missing side and the deltas. `delta_ns` / `delta_pct` are the change of `median_ns`.
  - `incomparable` is `true` when the baseline's `machine_fp` (`target`, `cpu_count` or `pionc_id`) differs from the current one; no verdict should be drawn from such a comparison.
- **`--profile` on benches**: the runner is linked against `libpionrt_prof.a` (Native) or the profiling Wasm runtime and run at a **fixed** iteration count (no calibration); the profiler is paused around setup and teardown and resumed strictly around the `bench_loop` iterations, so the profile covers only the timed body. The output is the unified profile report of §5.9, printed on stdout (one JSON document with `--json`, text otherwise); `--profile-out <path>` additionally writes the full JSON report atomically to `<path>`. Wall times measured under `--profile` include profiler overhead and are never a performance result.
- **Runner protocol** (internal, between `pionc` and the generated runner; listed for completeness): `<runner> --list` prints one `<index>\t<name>` line per bench; `<runner> --run <index> <iters> [--prof-win]` runs one bench and prints `PION_BENCH_US <microseconds>` for the timed window (`--prof-win` enables the `pion_prof_resume`/`pion_prof_pause` window). Bench bodies are emitted as `$__pion_bench_run_<index>`, timed with `pion_clock_monotonic_us`.

### 5.9 `pionc build|run --profile[=cpu|alloc|rc|all] [--dev] ...`, `pionc run --profile ... [--profile-out <path>] [--sample-rate <N>] [--profile-hz <Hz>] [--retained] [--json]` & `pionc profile summary|diff [--json] ...`
- **`--profile` modes** (`prof_mask`, §4.3): bare `--profile` = `cpu,alloc` (mask `3`); `--profile=cpu|alloc|rc|all` or a comma-separated subset (`--profile=cpu,alloc,rc`). `cpu` and `alloc` keep release inline RC, so CPU and allocation numbers reflect production code; `rc` compiles with inline RC disabled (`NO_INLINE_RC=1`) so every RC operation is observable.
- `--profile` **implies `--release`** unless `--dev` is given. On `pionc run` and `pionc bench`, `--sample-rate <N>`, `--profile-hz <Hz>` (default `997`) and `--retained` map to `PION_PROF_SAMPLE_RATE` / `PION_PROF_HZ` / `PION_PROF_RETAINED` (§4.3).
- **Errors** (machine-readable codes):
  - `E_PROFILE_STRIPPED` — `--profile` combined with a symbol-stripping linker flag (`-s`, `-S`, `-x`, `--strip-all`, `-Wl,-x`), passed directly or through `PION_LDFLAGS`.
  - `E_PROFILE_UNSUPPORTED_TARGET` — `--profile` for Windows (`amd64_win`), unsupported in this phase. Native profiling supports Linux x86_64, Linux ARM64 and macOS ARM64; Wasm32 profiles under Node.js.
  - `E_PROFILE_RT_CONFLICT` — `PION_RT_LIB` is set while `--profile` is requested without `PION_RT_PROF_LIB` (an uninstrumented runtime is never linked silently; unset `PION_RT_LIB` or set `PION_RT_PROF_LIB`).
  - `E_PROFILE_RT_MISSING` — no prebuilt `libpionrt_prof.a` was found and `runtime/pion_prof.c` is not available to build one.
- **Profile runtime lookup order**: `$PION_RT_PROF_LIB` (and `$PION_RT_CLI_PROF_LIB`) → `<exe_dir>/../lib/libpionrt_prof.a` → `out/libpionrt_prof.a` (or `../out/libpionrt_prof.a`) → an on-demand CAS build from `runtime/pion_prof.c` (§6) → `E_PROFILE_RT_MISSING`.
- **Wasm32**: `cpu` runs the module under `node --cpu-prof` (full stacks, `cpu_stack_mode: "full"`); `alloc`/`rc`/`retained` are recorded by `pion_wasm_rt.mjs` (default stack sample rate `64`).
- **`pionc build --profile[=...]`** links an instrumented binary (`-o <bin>` as usual) and prints no report; run it with `PION_PROF_OUT=<file>.pionprof.raw` (plus optional `PION_PROF_MODES`/`PION_PROF_SAMPLE_RATE`/`PION_PROF_RETAINED`, §4.3) and pass the raw file to `pionc profile summary`, which symbolizes it against the executable named on its `BIN` line.
- **`pionc run --profile`**: after the program exits the unified report is printed on **stdout** (one JSON document with `--json`, text otherwise); `--profile-out <path>` additionally writes the full JSON report atomically to `<path>` for later `pionc profile summary|diff`. When the profiled program itself prints to stdout, its output and the report share the stream: agents should read the report from `--profile-out <file.json>`.
- **`pionc profile summary <profile> [--top <N>] [--sort <key>] [--bin <path>] [--syms <path>] [--json]`**: `<profile>` is a saved report JSON or a raw `PIONPROF 1` file (symbolized against the executable on its `BIN` line, or `--bin <path>`, plus an optional `syms` sidecar `--syms <path>`). `--top` limits `top_functions[]` (default `20`); `--sort` ranks them by `self` (default, self CPU), `cum_cpu`, `alloc_bytes`, `cum_alloc_bytes`, `alloc_count`, `inuse_bytes` or `rc_ops`.
- **`pionc profile diff <base> <patched> [--top <N>] [--min-delta-pct <f>] [--json]`**: compares two reports (below; `--min-delta-pct` defaults to `3.0`).
- **Raw format `PIONPROF 1`** (line-oriented text, identical for Native C and Wasm32 JS):
  ```text
  PIONPROF 1
  META target=<t> modes=<mask> build_modes=<mask> cpu_stack_mode=<pc_only|full> sample_rate=<N> hz=<H> retained=<0|1> wall_us=<u64> cpu_us=<u64> peak_rss_kb=<u64> dropped_cpu=<u64> dropped_alloc=<u64> dropped_rc=<u64> retained_truncated=<0|1>
  META reserved_bytes=<u64> peak_reserved_bytes=<u64> backing_alloc_bytes=<u64> backing_alloc_count=<u64> backing_free_bytes=<u64> backing_inuse_bytes=<u64>
  ANCHOR <hex_runtime_addr> pion_prof_anchor
  BIN <executable_path>
  TAG <tag_id> <alloc_count> <alloc_bytes> <free_count> <free_bytes> <inuse_count> <inuse_bytes> <rc_inc> <rc_dec> <rc_atomic_inc> <rc_atomic_dec> <rc_destroy> <rc_immortal>
  TYPE <tag_id> <drop_fn> <alloc_count> <alloc_bytes> <free_count> <free_bytes> <inuse_count> <inuse_bytes>
  CPU_PC <hex_pc> <count>
  STACK <alloc|rc|inuse|backing> <tag_id> <count> <bytes> <frame0>,<frame1>,...
  ```
  - Native frames and `<drop_fn>` are hex PCs, symbolized offline from the executable's ELF64 `.symtab` / Mach-O `LC_SYMTAB` using the load slide `ANCHOR address − symtab address of pion_prof_anchor` (uniform for PIE, non-PIE and Mach-O executables). Wasm32 writes `sym:<wasm_function_name>` tokens and has no `ANCHOR`.
  - With `--profile`, Native codegen also caches a symbol sidecar per unit (`raw_sym\tpretty\tkind\tpkg\tfile\tline` per line) used to print exact closure / method / bench names with `file:line` without re-parsing sources.
- **Unified report JSON** (`pionc run|bench --profile --json`, `pionc profile summary --json`), `schema_version: 1`:
  ```json
  {"schema_version":1,"target":"amd64_sysv","modes":3,"build_modes":3,"cpu_stack_mode":"pc_only",
   "rc_partial":false,"sample_rate":1,"effective_cpu_interval_us":1003,"retained":false,"retained_truncated":false,
   "dropped_samples":{"cpu":0,"alloc":0,"rc":0},"wall_ms":412.7,"cpu_ms":409.9,"peak_rss_kb":5320,"total_cpu_samples":409,
   "managed":{"alloc_bytes":0,"alloc_count":0,"free_bytes":0,"free_count":0,"inuse_bytes":0,"inuse_count":0},
   "backing":{"alloc_bytes":0,"alloc_count":0,"free_bytes":0,"inuse_bytes":0},
   "allocator":{"reserved_bytes":0,"peak_reserved_bytes":0},
   "rc":{"inc":0,"dec":0,"atomic_inc":0,"atomic_dec":0,"destroy":0,"immortal":0},
   "by_type_tag":[{"tag_id":1,"tag_name":"String","alloc_count":0,"alloc_bytes":0,"free_count":0,"free_bytes":0,"inuse_count":0,"inuse_bytes":0,
                   "rc_inc":0,"rc_dec":0,"rc_atomic_inc":0,"rc_atomic_dec":0,"rc_destroy":0,"rc_immortal":0}],
   "by_type":[{"tag_id":4,"tag_name":"Struct","drop_fn_raw":"...","type_name":"Struct json::Node","alloc_count":0,"alloc_bytes":0,
               "free_count":0,"free_bytes":0,"inuse_count":0,"inuse_bytes":0}],
   "top_functions":[{"raw_sym":"...","name":"json::parse_value","category":"user","pkg":"json","file":"src/parse.pion","line":42,
                     "self_cpu_samples":120,"self_cpu_pct":29.3,"cum_cpu_pct":null,"self_alloc_bytes":0,"cum_alloc_bytes":0,
                     "alloc_count":0,"inuse_bytes":0,"rc_ops":0}],
   "hints":[{"code":"H_STRING_ALLOC_STORM","severity":"high","target":"String","message":"...",
             "evidence":{"metric":"string_alloc_share_pct","value":71.2,"threshold":45.0,"samples":52000},
             "suggested_cmd":"pionc profile summary --sort alloc_bytes <profile.json>"}]}
  ```
  - Honesty fields: `modes` (requested) vs `build_modes` (compiled); `rc_partial: true` when `rc` was requested but the binary inlines RC (RC counts are then incomplete); `cpu_stack_mode` (`"pc_only"` ⇒ `cum_cpu_pct` is `null`); `sample_rate` (stack sampling only — domain and per-tag totals are exact); `effective_cpu_interval_us` (`1000000 / hz`); `dropped_samples` (table overflow); `retained_truncated`.
  - The four memory domains never overlap: `managed` (RC objects), `backing` (raw buffers behind arrays, maps, strings and string builders), `allocator` (OS memory reserved by the allocator), `rc` (operation counts). `by_type_tag[]` splits `managed` + RC counts by runtime type tag (`String`, `Bytes`, `Array`, `Struct`, `Enum`, `Closure`, `Map`, `Channel`, `Mutex`, `Atomic`, `StrBuf`, `Scope`, `World`, else `Tag(<n>)`); `by_type[]` further splits by `(tag_id, drop function)`, naming concrete user types (`type_name`, e.g. `Struct json::Node`; `Struct (no-drop)` / `Enum (no-drop)` for types without a drop function).
  - `top_functions[].category` is one of `user`, `runtime_mem`, `runtime_rc`, `runtime_std`, `external`. In release builds inline RC is attributed to the calling user function.
- **`hints[]`** — every hint has `{code, severity, target, message, evidence: {metric, value, threshold, samples}, suggested_cmd}`; all thresholds are hard gates to keep noise out:
  | `code` | Emitted when | `evidence.metric` |
  |---|---|---|
  | `H_LOW_SAMPLES` (`info`) | `target: "cpu"`: CPU mode on and `total_cpu_samples < 100` (suppresses `H_HIGH_RUNTIME_MEM_CALLS`); `target: "alloc"`: alloc mode on and `managed.alloc_count < 1000` (suppresses `H_STRING_ALLOC_STORM`) | `cpu_samples` / `alloc_count` |
  | `H_HIGH_RUNTIME_MEM_CALLS` | `total_cpu_samples >= 100` and self CPU share of `runtime_mem` functions `>= 20.0%` (a runtime-call share; inline RC counts toward user functions) | `runtime_mem_cpu_pct` |
  | `H_STRING_ALLOC_STORM` | (`managed.alloc_bytes >= 1048576` or `managed.alloc_count >= 10000`) and `String` share of managed alloc bytes (of counts when bytes are 0) `>= 45.0%` | `string_alloc_share_pct` |
  | `H_CONTAINER_GROW_CHURN` | backing bytes allocated under `pion_arr_grow` / `pion_arr_push_flat_grow` / `pion_map_grow` / `pion_strbuf_grow` `>= 262144` and `>= 30.0%` of `backing.alloc_bytes` | `container_grow_backing_pct` |
  | `H_HIGH_RC_TRAFFIC` | `rc_total = inc + dec + atomic_inc + atomic_dec + destroy >= 100000` and one function accounts for `>= 25.0%` of it (`target` = that function) | `top_fn_rc_share_pct` |
  | `H_HIGH_ALLOCATOR_OVERHEAD` | `allocator.peak_reserved_bytes >= 4194304`, live bytes (`managed.inuse_bytes + backing.inuse_bytes`) `> 0`, and `peak_reserved_bytes >= 2 ×` live bytes | `peak_reserved_to_inuse_ratio` |
- **Diff JSON** (`pionc profile diff --json`): `{"schema_version":1,"target":"...","summary":{"wall_ms":D,"peak_rss_kb":D,"managed_alloc_bytes":D,"managed_alloc_count":D,"managed_inuse_bytes":D,"backing_alloc_bytes":D,"peak_reserved_bytes":D,"rc_total":D},"improved":[F],"regressed":[F],"new":[F],"gone":[F]}` where `D = {"base","patched","delta","delta_pct"}` and `F = {"raw_sym","name","category","status","base_self_cpu_pct","patched_self_cpu_pct","delta_cpu_pct","base_alloc_bytes","patched_alloc_bytes","delta_alloc_bytes","delta_alloc_pct","base_rc_ops","patched_rc_ops","delta_rc_ops"}`. A function counts as improved/regressed only when its CPU-share change (else its relative alloc change) reaches `--min-delta-pct`. Use `diff` to confirm *where* a change moved cost; confirm *how much faster* only with a clean `pionc bench --compare`.

## 6. Global Content-Addressed Cache (CAS) & `pion.toml` Contract

- **Package Manifest (`pion.toml`)**:
  ```toml
  [package]
  name = "app"
  version = "0.1.0"

  [dependencies]
  math = { path = "../math" }
  regex = { git = "https://example.com/pion-std.git", tag = "v0.3.0", subdir = "std/regex" }
  # exactly one of tag = / rev = / branch = (none: the remote HEAD); subdir is optional

  mylib = { git = "https://example.com/mylib.git", tag = "v1", version = "1.0.0", registry = "https://example.com/index.git" }
  # written by `pionc add` from a registry: `registry` and the index `version` let `pionc update` re-read it

  [link]
  libs = ["sqlite3"]            # or: lib = "sqlite3" (de-duplicated, first-seen order)
  frameworks = []               # or: framework = "..." (macOS only; ignored on Linux)
  search_paths = ["./lib"]      # or: search_path = "..." (-L<path>, relative to package dir)
  rpaths = ["@executable_path/../lib"] # or: rpath = "..." (-Wl,-rpath,<path>; `/`, `@`, `$` kept verbatim)
  objects = ["vendor/libfoo.a"] # or: object = "..." (precompiled .a/.o/.dylib/.so; relative to package dir)
  flags = []                    # extra linker flags (order-preserving, not de-duplicated)
  c_sources = ["csrc/shim.cc"]  # or: c_source = "..." (compiled to CAS obj/cstub_<key>.o)
  cc_flags = ["-O2", "-Iinc"]   # C/C++/ObjC compiler flags (order-preserving; relative `-I<path>` resolved to package dir)

  [link.macos]                  # merged after [link] when target OS is macOS (`arm64_apple`, `amd64_apple`)
  frameworks = [
    "Cocoa",
    "Metal",
  ]

  [link.linux]                  # merged after [link] when target OS is Linux (`amd64_sysv`, `arm64`, `rv64`)
  libs = ["freetype", "fontconfig"]

  [link.ios]                    # optional; merged after [link] for `ios_arm64`, `ios_sim_arm64`
  frameworks = ["UIKit", "Metal"]

  [link.android]                # optional; merged after [link] for `android_arm64`, `android_x64`
  libs = ["log", "android"]

  [link.windows]                # optional; merged after [link] for `amd64_win`
  ```

  - `[targets]` declares file-level conditional compilation rules mapping normalized relative file paths (`\` → `/`, leading `./` stripped; empty paths, absolute paths, and `..` segments are rejected) to a non-empty array of target predicates with **OR** semantics. Allowed predicates are the 11 exact targets (`arm64_apple`, `amd64_apple`, `amd64_sysv`, `amd64_win`, `arm64`, `rv64`, `ios_arm64`, `ios_sim_arm64`, `android_arm64`, `android_x64`, `wasm32`) plus group/OS predicates: `native` (the 10 non-`wasm32` targets), `wasm` (`wasm32`), `macos` (`arm64_apple|amd64_apple`), `linux` (`amd64_sysv|arm64|rv64`), `windows` (`amd64_win`), `ios` (`ios_arm64|ios_sim_arm64`), `android` (`android_arm64|android_x64`), and `unix` (`macos|linux|ios|android`). Empty arrays `[]`, unknown predicates, or listed files missing on disk are manifest/load errors. Unlisted files are active on all targets. Filtering runs against the exact requested target (before QBE architecture mapping, so `android_x64` never matches `linux`) for both source and `*_test.pion` files (with dependency packages evaluated against the consumer's active target) prior to parsing, `.pionsig`/`.pionstub`, SSA/Wasm codegen, and CAS keying; `pionc fmt` continues to format all `.pion` files.
  - `[verify]` accepts only `enabled = true|false` (other keys / values are rejected with the line number). The driver lowers `enabled = true` by appending the file-level attribute `#![verify]` after the last line of each of the package's sources (no line / column shift; the switch is thereby part of every source-content CAS key), so the marks also reach `.pionsig` / `.pionstub` and downstream `#verify` callers.
  - **Multi-Package Workspaces (`[workspace]` & `[workspace.dependencies]`)**:
    - A root `pion.toml` may declare `[workspace]` with `members = ["packages/*", "cmd/*"]` (exact paths or single-segment wildcards, multiline arrays and singular `member` supported; unknown keys rejected with line number) and `[workspace.dependencies]` (same `path` / `git`+`tag|rev|branch|subdir` / `registry` syntax; `workspace = true` forbidden inside `[workspace.dependencies]`).
    - Both **virtual roots** (`[workspace]` without `[package]`) and **hybrid roots** (`[package]` + `[workspace]`) are supported; hybrid roots include themselves as a member.
    - Member packages inherit dependencies via `foo = { workspace = true }` in `[dependencies]` (combining `workspace = true` with `path`/`git`/`registry` is an error with line number). `pionc` walks up to 16 parent directories from any member package (checking literal ancestors first, then canonical physical ancestors) to discover the nearest enclosing `[workspace]` whose declared `members` (or hybrid root itself) includes that package's canonical physical directory — packages not listed in `members` stay standalone — rewrites inherited `path` dependencies relative to the workspace root, and shares a single `<ws_root>/pion.lock`. Inheritance is resolved per package: `{ workspace = true }` in an external `path`/`git` dependency resolves against the nearest `[workspace]` that declares *that* dependency package as a member (never the consuming root's workspace), is never redirected onto a same-named root pin, and is an error when no workspace declares it.
    - From a workspace root (explicit path or default `"."`), `check [--fix]`, `test [--package|-p <name>]`, `fmt [--check]`, `doc`, `query defs|sig|callers|deps|analyze`, and `fetch` operate across all workspace members; `build` and `run` accept `--package <name>` / `-p <name>` (and on a virtual root without `--package`, auto-select the unique member defining `fn main` or report available members).
  - **Multiline arrays**: any `key = [ ... ]` value in `pion.toml` may span multiple lines (with `#` comments and optional trailing commas). Unknown keys in `[link]` / `[link.macos]` / `[link.linux]` / `[link.ios]` / `[link.android]` / `[link.windows]` are rejected with the line number.
  - **C/C++/ObjC stub compilation (`c_sources`)**: each package's active `c_sources` are compiled in topological order (`.cc`/`.cpp`/`.mm` with `$CXX` or `c++`, `.c`/`.m` with `$CC` or `cc`), automatically passing `-I<runtime_dir>` (and `<runtime_dir>/../runtime` when `pion_rt.h` resides there) so stubs can `#include "pion_rt.h"`. Objects are written atomically to `$PION_CACHE_DIR/obj/cstub_<final_key>.o` (LRU-tracked, zero source-tree pollution, published under `index.tsv.lock` after pinning so concurrent evictors cannot race cold publishes) using two-layer `cstub-v3` ccache Direct Mode: `base_key = sha256("cstub-v3|" + target + "|" + pkg_name + "|" + compiler + "|" + cc_ver_fp + "|" + eff_cc_flags + "|" + rt_inc_dirs + "|" + norm_src + "|" + sha256_bytes(src))`, paired with a `v3` dependency manifest `$PION_CACHE_DIR/obj/cstub_dep_<base_key>.deps` (header count + lexical paths + `absent:<n>` negative-cache shadow paths + trailing `sha256:` integrity digest) recorded from the compiler's real dependency output (`-MD -MF` for GCC/Clang/MinGW/Zig with strict target/source verification, `/clang:-MD /clang:-MF` for `clang-cl`, `/sourceDependencies` for `cl.exe` parsed by a full strict JSON parser; older VS 2019 `< 16.7` `cl.exe` without `/sourceDependencies` degrades fail-closed to uncached recompilation). Manifests store lexical absolute header paths preserving symlinks and `..` segments (so retargeting a symlinked header or symlinked directory always misses) and hash raw bytes via `pion_cli_sha256_file` (bypassing in-process hash memos on cold publish, followed by post-hash race verification). On cache HIT, `pionc` verifies every recorded header's content hash and checks only the manifest's `absent:` negative-cache paths (shadow candidates that did not exist at compile time across higher-priority `[src_dir] + user_I_dirs + rt_inc_dirs` and project header parent directories — zero false positives on pre-existing dual headers / `#include_next`, zero false negatives on newly introduced shadows); on compile-time race detection (`pion_cli_path_change_ms` / `pion_cli_lpath_change_ms` walking source, headers, ancestor directories, and intermediate symlink components + targets against `pre_hash_ms`, or post-compile source hash mismatch), `.deps` publication is skipped fail-closed so the next run self-heals.
  - **Linker & binary cache key**: when all packages have no `frameworks`, `search_paths`, `rpaths`, `objects`, `flags`, or C++ sources/libs (`has_cxx`), macOS keeps its direct `ld` fast path. Otherwise both macOS and Linux link through `$CXX`/`c++` (when `has_cxx`) or `$CC`/`cc` with argument order `obj_paths` (including `cstub_*.o`) → `libpionrt.a` → `objects` → `-L<search_paths>` → `-Wl,-rpath,<rpaths>` → (macOS: `-framework <fw>`) → `-l<libs>` → `flags` → (Linux: `-lm -lpthread`). Both `pionc build`/`run` and `pionc test` include all resolved link options plus pure-content fingerprints (explicit CAS keys for CAS-produced `.o`s, streaming `pion_cli_sha256_file` for external `objects` and `.rc` resource directories — zero `mtime` in any CAS key so cross-runner cache restores achieve 100% HIT).
- **Git dependencies, `pion.lock`, `--locked` & `--offline`**: git dependencies resolve into the global shared cache `$PION_CACHE_DIR/git/` (default `~/.cache/pion/git/`): bare mirrors `repos/<sha256(url)>.git` and read-only checkouts `checkouts/<rev>` (no `.git`), created atomically and shared zero-copy by every worktree. `<root>/pion.lock` pins each git dependency to a full commit (40 or 64 lowercase hex digits; anything else is a parse error) (`version = 1`, then `[[package]]` tables with `name`, optional `package`, `git`, `ref`, `rev`, `subdir`, sorted); legacy v1 lockfiles without `package` remain 100% readable (treating `name` as the package name), distinct `ref`s of the same package/repo coexist cleanly, and ambiguous matching entries with different `rev`s fail with an error. A locked dependency whose checkout exists runs no `git` at all; tags and full revs resolve from the mirror, branches and HEAD always fetch. Only `<root>/pion.lock` is ever written, and only when it changes. Passing `--locked` or `--offline` to `check`/`build`/`run`/`test`/`fetch` forbids silently rewriting `pion.lock` (`--locked` requires all git deps to match `pion.lock`; `--offline` forbids network git clone/fetch).
- **`pionc fetch [--locked] [--offline] [--json] [dir]`**: resolves every git dependency, writes/verifies `pion.lock`, and prints `{"ok":true,"lock":"...","git_cache":"...","packages":[{"name","canon_id","dir","source":"path|git"}],"git":[{"name","git","ref","rev","subdir"}]}`.
- **Git-index registry**: a registry is any git repository (URL or local path) holding a root `catalog.json` and/or one `index/<name>.toml` per package: `name = "..."` (optional, must match), `version = "..."`, `git = "..."`, at most one of `tag` / `rev` / `branch`, optional `subdir`. Its index is mirrored in `$PION_CACHE_DIR/registry/<sha256(url)>.git` (default `~/.cache/pion/registry`; `url` is the normalized source below), refreshed on every `add`/`update` that reads it (no TTL); the package itself resolves like any git dependency. Every `git` call that takes an external URL passes it after `--`, and a registry or git URL (or revision) starting with `-` is refused, so no URL can become a `git` option; `git` always runs with `GIT_TERMINAL_PROMPT=0` and `GIT_ALLOW_PROTOCOL=file:http:https:ssh` (no `ext::` or other transport helpers), and its stderr never reaches the terminal raw: on POSIX hosts it is captured (via `sh` + `mktemp`) and, when the command fails, appended to the error with every control character neutralized; on Windows hosts (no `sh`) it is discarded. Mirrors are cloned into a temporary directory created exclusively by the runtime's `pion_fs_mkdir_excl_status` (POSIX `mkdir(path, 0700)` / Windows `CreateDirectoryW`; no subprocess, no command interpreter; each try takes a fresh `pion_cli_next_seq`, only a taken name moves on, up to 32) and renamed into place; failing to create one is an error. A mirror's only published reference is its detached `HEAD` (also its `git gc` reachability root): a mirror is cloned aside, must resolve `HEAD` to a commit (an empty registry, or one whose `HEAD` names no commit, is never cached), gets `update-ref --no-deref HEAD <commit>`, and only then is renamed into place — an unusable mirror left by an older pionc is replaced the same way, never fetched in place, under an exclusive kernel lock on the file `<mirror>.replace.flock` (`pion_fs_trylock`: `flock` / `LockFileEx`, released by the kernel when the holder exits or is killed; the lock file stays; upgrading assumes no concurrent older `pionc` process still holds an active legacy `<mirror>.replace.lock` directory lock, while leftover `.replace.lock` directories are ignored) and re-checked under that lock, so a mirror repaired concurrently is kept as the winner; if swapping in the new mirror fails and the old one cannot be moved back, its backup is kept and its path reported; and a symbolic `HEAD` left by an older pionc is migrated once with a compare-and-swap `update-ref --no-deref HEAD <old> <old>` (a concurrent publish is never overwritten). A refresh writes no ref before its network steps: a single `fetch --prune -- origin +refs/heads/*:refs/heads/* +refs/tags/*:refs/tags/*` (which never moves a detached `HEAD`), `ls-remote --symref origin HEAD`, and an explicit fetch of the advertised branch or detached commit when it is not yet local; only then is the advertised commit published with one atomic compare-and-swap `update-ref --no-deref HEAD <new> <old>` against the commit the refresh started from (no network), so a slower refresh never overwrites a newer concurrent publish (it fails as `stale` and reads the winner), and the stamp is renewed. Any failure (unreachable remote, an upstream `HEAD` that advertises no commit, a deleted or force-pushed branch) leaves `HEAD` on the last published commit, so that snapshot stays readable (`search` reports `stale`, `--offline` keeps working) and the stamp is not renewed; every ref update is checked.
- **Registry source (shared by `add` and `search`)**, first match wins: (1) `--registry <url_or_path>` (a local path is relative to the working directory); (2) `[registry] url` of the project's `pion.toml` (a local path is relative to **that `pion.toml`'s directory**; for `search`, the `pion.toml` in the working directory — none is fine, an unreadable or unparsable one is `E_INVALID_MANIFEST` even when `--registry` is given); (3) `$PION_REGISTRY` (`""` counts as unset; `none` / `off`, any case, disable level 4 and fail with `E_REGISTRY_DISABLED`, never overriding levels 1–2; a local path is relative to the working directory); (4) the official registry `https://github.com/AFK-surf/pion-packages.git` (a private repository: reading it needs git access to it). A location containing `://`, or scp-style `[user@]host:path` (a `:` before any `/` or `\`, not a Windows drive letter such as `C:`), is a remote URL kept as given; anything else is a local path (`/...` and Windows drive paths `C:`, `C:/...`, `C:\...` are absolute; a bare `C:` is the drive root `C:/`, while `g:repo.git` is an scp-style remote). An empty `--registry ""` is `E_INVALID_ARGS`. Local paths are made absolute and normalized (`.`/`..` folded, byte for byte so UTF-8 directory names survive) before keying the mirror, so the same registry reached through a `pion.toml`-relative and a working-directory-relative path shares one mirror. `pionc update` keeps using the `registry` each dependency recorded in `pion.toml`.
- **`pionc add [--json] <name> (--path <p> | --git <url> [--tag <t>|--rev <r>|--branch <b>] [--subdir <s>] | [--registry <url_or_path>]) [dir]`**: sets `[dependencies] <name>` in `pion.toml` in place (only that line changes; idempotent), resolves it into the shared cache and `pion.lock`, and prints `{"ok":true,"action":"add","package":"...","source":"path|git|registry","location":"...","version":"...","rev":"...","changed":bool}`. Without `--path`/`--git` the registry is chosen as above (with `$PION_REGISTRY=off` and no other source: `{"ok":false,"code":"E_REGISTRY_DISABLED","error":"no source for ..."}`). A git source whose `pion.toml` declares another package name, an unknown registry package or a failed fetch print `{"ok":false,"error":"..."}` and restore `pion.toml` and `pion.lock` byte for byte.
- **`pionc search [--json] [--offline] [--refresh] [--registry <url_or_path>] [--category <cat>] [query...]`**: lists the registry's packages.
  - *Matching*: every query word (arguments split at ASCII whitespace; `--` ends options) must occur, ASCII case-insensitively, in the package's `name`, `summary` or one of its `keywords` (AND); `--category` keeps only packages whose `category` equals it ASCII case-insensitively (an empty category never matches). No query lists every package. Order: a word equal to the name, then a word prefixing the name, then the rest; ties by name (byte order).
  - *Freshness*: the mirror records the wall-clock time of its last **successful** clone/fetch that left `HEAD` resolving to a commit (`.pion_last_fetch`; a failed fetch never renews it). Online, a mirror fetched less than 10 minutes ago is read without `git fetch`; `--refresh` always fetches. If the clone/fetch fails (offline, a concurrent ref lock) and the mirror's `HEAD` still resolves to a commit, the cached index is used and the result carries `"stale":true` (human mode: a warning on stderr). A mirror whose `HEAD` resolves to no commit (none cached, an empty repository, a default branch that is gone) is unusable: `E_REGISTRY_UNREACHABLE`. `--offline` never runs a clone/fetch nor creates any directory: it reads a usable mirror or fails with `E_REGISTRY_UNREACHABLE`. `--offline` with `--refresh` is `E_INVALID_ARGS`.
  - *Snapshot*: `HEAD` is resolved once to a commit OID and every read uses that commit. If the commit's root has `catalog.json`, it is the only source: strict RFC 8259 JSON (UTF-8 checked) with `"schema_version": 1` and a `packages` array of objects with `name` (required, a valid package name `[A-Za-z_][A-Za-z0-9_-]*`) and optional `version`, `tag`, `subdir`, `category`, `summary` (strings), `keywords`, `deps` (string arrays), `wasm32`, `world_free` (booleans); a missing optional field takes its default, an explicit `null` is a type error; unknown keys are ignored. Invalid JSON, a wrong field type, an invalid name or another `schema_version` is `E_REGISTRY_INVALID_CATALOG` — never a silent fallback. Only when `catalog.json` is absent are the legacy `index/` entries read: the regular-file children of `index/` (`git ls-tree -z`) named `<name>.toml` with a valid package name (`.gitkeep`, subdirectories and other names are skipped), fetched with one `git cat-file --batch` (OIDs fed from a temporary list file on stdin, so no argv limit; output split by each header's exact byte size, trailing bytes rejected; on Windows one `git cat-file blob` per entry) and parsed as index entries (`category`, `summary`, `keywords`, `deps` empty, `wasm32` / `world_free` `null`). A commit with neither, or an unparsable entry, is `E_REGISTRY_INVALID_CATALOG`.
  - *Output*: `--json` prints `{"ok":true,"registry":"...","source":"flag|manifest|env|default","commit":"<oid>","format":"catalog|index","stale":bool,["warning":"...",]"count":N,"packages":[{"name","version","tag","subdir","category","summary","keywords":[...],"deps":[...],"wasm32":bool|null,"world_free":bool|null,"installable":bool}]}` (`installable`: the same commit has `index/<name>.toml`, i.e. `pionc add <name>` can resolve it; `wasm32` / `world_free` are `null` whenever the registry does not state them — a `catalog.json` entry that omits the key, or any legacy `index/` entry — while an explicit `null` inside `catalog.json` is rejected as above); strings are copied byte for byte (UTF-8 kept as is, only `"`, `\`, control characters and DEL escaped; a malformed UTF-8 byte becomes `\ufffd`). Zero matches is success (`"count":0,"packages":[]`, exit `0`). Human mode prints one `name  version  category  summary` row per package with every C0/C1 control character and DEL replaced (no escape sequence from a registry reaches the terminal), then the count and an `install: pionc add <name> [--registry <url>]` hint for the first installable, validly named match (the registry shell-quoted when needed; none when nothing is installable, or when a `--registry` location contains control characters and so cannot be shown losslessly).
  - *Errors*: exit `1` with `{"ok":false,"code":"...","error":"..."}` (`--json`) or `error[CODE]: ...` on stderr. Stable codes: `E_INVALID_ARGS` (unknown option, missing option value, `--offline --refresh`, a registry starting with `-`), `E_INVALID_MANIFEST`, `E_REGISTRY_DISABLED`, `E_REGISTRY_UNREACHABLE`, `E_REGISTRY_INVALID_CATALOG`.
- **`pionc check --fix [--json] [path...]`**: runs up to 3 fix rounds, applying non-overlapping `TextEdit` patches per file in descending byte-offset order atomically, then re-checks and prints `{"ok":bool,"fixed":N,"files":[...],"diagnostics":[...]}` (exit `0` when clean, `1` when diagnostics remain).
- **`pionc remove [--json] <name> [dir]`**: removes `<name>` from `[dependencies]` in `pion.toml` (preserving all other comments, formatting, and sections), prunes unreferenced entries from `pion.lock` when present, and prints `{"ok":true,"removed":"<name>","manifest":"..."}`.
- **`pionc doctor [--json]`**: verifies toolchain self-location and host dependencies (`version`, `host_target`, `pionc`, `qbe`, `rt_lib`, `wasm_rt`, `cc`, `cxx`, `win_abi`, `wasm_opt`, `node`, `git`, `cache_dir`, `cache_files`, `cache_bytes`, `cache_max_mb`); exits `0` iff core dependencies (`qbe`, `rt_lib`, `cc`) exist.
- **Atomic output publishing**: every executable `pionc build`/`run`/`test` links (native CAS `bin/` entries, test binaries and `-o`) and every single-package Wasm32 / `--emit-obj` / CAS-copied `-o` file is first written under its own basename into a private staging directory `<dir>/.pion_ld.<pid>.<seq>` (created exclusively with `pion_fs_mkdir_excl_status`, `pid` from `pion_cli_getpid`, a fresh `seq` from `pion_cli_next_seq` on every attempt, so no two threads of one `pionc` (`test --jobs N`) ever try the same name and a removed name is never reused; a taken name (a same-pid leftover of an older process, a foreign file) is skipped and left untouched, up to 4096 names, and any other `mkdir` failure is an immediate error naming the path) next to the output — so the linker's `-o` carries the final basename (Apple ld64 records it as the ad-hoc code-signature identifier, making identical CAS links byte-identical across processes) and the staged name is never longer than the final one — then renamed into place only after the linker / writer succeeded and its staged output is a non-empty regular file (a tool exiting 0 with no, an empty or a symlinked output fails the build and replaces nothing; `wasm-opt` reads its input from a second private staging directory, so input and output never alias); the staging directories are removed recursively without following symlinks on success and failure alike (an entry's kind is checked with `lstat` first; symlinks and Windows junctions are removed themselves, never listed); a failure before publishing publishes nothing (a cleanup failure is appended to the tool error), and a cleanup failure after publishing fails the command with an error naming both the published output and the leftover staging directory (`published <out>, but failed to remove staging directory <dir>`). Directory/basename splitting uses the host's separators (`pion_cli_is_windows`; a backslash is an ordinary file-name character outside Windows). An extension-less Windows `<out>` is published as `<out>.exe` (matching the GCC/Clang drivers), and a Windows test binary's CAS index key carries the same `.exe` (`cas_linked_exe_name`). A CAS entry (binary hit, test binary, Wasm module, or a lost rename race's winner) counts as present only as a non-empty regular file (never a directory, symlink or 0-byte file); a lost rename race on a content-addressed CAS output (e.g. Windows refusing to replace a running binary) succeeds only then. For a user-named path (`-o`, `--emit-*`, `pionc fmt`/`check --fix` sources, `pion.toml`, `pion.lock`) a failed rename is always an error and an older file at that path is never reported as the output. Every read-modify-write of `$PION_CACHE_DIR/index.tsv` (CAS record/evict, `pionc cache prune`) and `pionc cache clear` / `pionc clean` hold a blocking exclusive `pion_fs_lock` on `index.tsv.lock` (never removed) and publish the new index strictly. When the lock cannot be taken, or anything other than a readable regular file sits at `index.tsv` (checked with `lstat`: a directory or a symlink, dangling or not), the index and every cached file are left untouched: builds skip the LRU update, while `cache prune` / `cache clear` / `clean` fail (non-zero exit, `ok:false`); `cache prune` also fails when the index cannot be written, and `cache clear` / `clean` when it cannot be removed. Single-package Wasm32 CAS keys include whether (and which) `wasm-opt` ran.
- **`pionc cache stats|prune|clear [--all] [--json]` & `pionc clean [--all] [--json]`**: inspects CAS buckets (`obj`, `bin`, `sig`, `git`), runs LRU eviction against `$PION_CACHE_MAX_MB` (respecting active peer pins in `pins/`), or explicitly wipes build caches (`clear` / `clean` is an explicit full wipe and does not preserve active peer pins; `--all` also clears `git/` and `registry/`).
- **Relocatable Zero-Env Layout & Default Target `"."`**: `pionc` locates itself via `argv[0]` / `$PATH`, resolves every symlink on that path (`pion_fs_canon_path`, falling back to the path as found; relative, absolute and multi-hop links) to the real executable, and resolves `<prefix>/bin/{pionc,qbe}`, `<prefix>/lib/libpionrt.a`, and `<prefix>/share/pion/{pion_wasm_rt.mjs,runtime/pion_rt.{c,h}}` automatically without requiring `PION_*` environment variables (while still honouring explicit env overrides and in-tree `out/`). When `check`, `build`, `run`, `test`, `fmt`, or `doc` is invoked without a path argument and the current directory contains `pion.toml` or `src/`, the target defaults to `"."`. `pionc --help` / `-h` / `help` prints full usage to stdout and exits `0`; `pionc --version` / `-V` / `version` prints `pionc 0.1.0 (<host_target>, abi <abi_rev>, self-hosted)` (or `{"version":"0.1.0","target":"...","abi_rev":"..."}` with `--json`, where `abi_rev` comes from `pion_compiler_abi_rev()`).
- **`pionc update [--json] [pkg] [dir]`**: re-reads the registry entry of every registry dependency (or only `pkg`), drops its lock pin, re-resolves every git dependency to its newest target ref, rewrites `pion.lock` and type-checks the workspace; prints `{"ok":true,"action":"update","packages":[{"name","ref","from","to","updated":bool}]}`. Updating a path dependency is an error; a failed resolution or a workspace that no longer checks restores `pion.toml` and `pion.lock` (`"check"` carries the diagnostics).
- **`pionc init [--template cli|service|invar-app] [--json] <dir>`**: scaffolds a package named after the directory (`[a-z0-9_]`) using the chosen template (default `cli`: `pion.toml`, `src/main.pion`, `main_test.pion`; `service`: adds `src/worker.pion` with `scope`/`spawn`/`Channel`; `invar-app`: dual-thread GUI skeleton with `src/protocol.pion`, `src/worker.pion`, `#render_thread`-guarded `src/view.pion`, `src/main.pion`, `main_test.pion`). The result passes `check`, `test`, `run` and `fmt --check` as is; JSON output includes `"template"`. Refuses to overwrite existing files or accept unknown template names.
- **Cross-package traits & generics**: an imported package's `impl Trait for Type` is registered under `pkg::Trait::pkg::Type` (built-in targets such as `Int` stay unqualified), and impl symbols use the package-local trait/type names, so definitions and cross-package calls link. Any package exporting a `pub` generic fn or method (`type_params.length() > 0`) skips `.pionstub` (importers monomorphize from its source) and exports its package-prefixed internal functions and constants at the QBE level so cross-package monomorphized bodies link cleanly while `types.mbt` still enforces `E_PRIVATE_SYMBOL`.
- **Cross-Package Incremental Isolation**: Downstream package CAS keys depend ONLY on upstream packages' `pub` `.pionsig` SHA-256 hashes (never upstream function bodies). Editing an upstream function body without changing its `pub` `.pionsig` yields 100% CAS hit on downstream `.o` files, `pionc check` `.pionsig`/`.pionstub` entries, and multi-package `--target wasm32` `.ssa`/`.wasm` entries.
- **Incremental `pionc check` & Multi-Package `wasm32` CAS**:
  - `pionc check` and `pionc check --fix` cache clean packages' `.pionsig` and `.pionstub` in `$PION_CACHE_DIR/sig/` keyed by `(pkg_sources, upstream_.pionsig_hashes, "check", self_fp)` (using only the running `pionc` binary fingerprint without probing `qbe`/`libpionrt.a`). Packages that emit diagnostics or depend on an errored upstream are never cached.
  - Multi-package `pionc build --target wasm32` caches each package's `.pionsig`/`.pionstub`/`.ssa` in `$PION_CACHE_DIR/{sig,ssa}/` and the final `.wasm` binary (including `wasm-opt` identity when active) in `$PION_CACHE_DIR/bin/wasm_<key>.wasm`, skipping `emit_wasm_from_ssa` and `wasm-opt` on binary CAS hit when `--emit-ssa` is not requested. Setting `PION_TRACE_CAS=1` logs `[cas-check]`, `[cas-wasm]`, and `[cas-wasm-bin]` HIT/MISS lines to stderr.
- **Demand-Driven Constant Initialization Planner Diagnostics**: `compute_const_init_plan_from_pkg_tc` runs a demand-driven BFS over `#cdep` seeds and reachable local function summaries (with fail-closed fallback to full emission) that produces the exact same 5-field `ConstInitPlan` (`order`, `has_cycle`, `cycle_path`, `plan_hash`, `has_ambiguous_method`) as full emission without changing `.pionsig` or `usig/*.sig` formats. Three opt-in debug environment variables govern CLI runs:
  - `PION_SIG_VERIFY_DEMAND=1`: runs both the demand-driven planner and the full planner on every package checked/built and panics immediately on any 5-field mismatch.
  - `PION_SIG_FORCE_FULL=1`: bypasses the demand-driven planner and runs the full planner directly (for A/B timing comparisons).
  - `PION_SIG_TRACE_DEMAND=1`: emits `[sig-demand] pkg=<name> stage=<0..3> scanned=<k>/<n> fallback=<reason>` summary lines to stderr at process exit.
- **Compiler Fingerprint**: Every CAS key (`cas_compute_key`, `cas_compute_unit_key`) and `.usig` cache prefix includes `compiler_fp = sha256(PION_COMPILER_ABI_REV | qbe_size | libpionrt_size | salt)`, where `salt` = `selfid:<image_id>|objpol:k1a-v1|as:<as_flags>|$PION_CACHE_SALT` using the running `pionc` binary's zero-I/O in-memory image identity (`pion_cli_self_image_id`: Mach-O `LC_UUID` on macOS, ELF `NT_GNU_BUILD_ID` via `dl_iterate_phdr` with `stat("/proc/self/exe")` `dev:ino:size:mtime_ns` fallback on Linux, and PE headers + CodeView GUID on Windows; falling back to `self:<pionc_size>:<pionc_mtime_ms>` only when no image identity is available, plus target assembly policy flags such as `-Wa,-mbig-obj` on `amd64_win`) and `PION_COMPILER_ABI_REV` is currently `pionc-v0.24` (Wave AA3: non-generic structs and niche enums drop through the canonical file-local `$pion_drop_slots_<key>` helper, removing the exported `$pion_drop_struct_*` and tagless `$pion_drop_enum_*` symbols, and tagged enums without RC fields allocate with a null drop function; `pionc-v0.23` added CLBG Track P1: declaration-level 2-variant null-niche `enum` representation with `0` unit variant, tagless `payload_offset = 0` payload variant, boxed `Option[NicheEnum]`, and Wasm32 P47-A `$pion_drop_enum_*` slot-mask recognition; `pionc-v0.22` added Wave K1-A Windows COFF per-symbol sections + `.linkonce one_only` + same-section jump tables + `-Wa,-mbig-obj`, Mach-O text `.subsections_via_symbols`, MinGW `-Wl,--gc-sections` / MSVC `/OPT:REF /OPT:NOICF /INCREMENTAL:NO`, and `c_sources` `-ffunction-sections -fdata-sections` / `/Gy /Gw`; `pionc-v0.21` added first-class immutable `Send` sequence type `ImmArray[T]`; `pionc-v0.20` added Wave J4b Cargo-style `package = "..."` dependency aliases, source-hashed canonical package IDs `canon_id`, alias-aware CAS keys, and `E_DUPLICATE_C_SYMBOL`; `pionc-v0.19` added unboxed 1-based `l` representation for non-generic payload-less enums + zero-alloc null-niche `Option[UnitEnum]`; `pionc-v0.18` added compact 4-byte `Array`/`FixedArray` slots for `Int`/`UInt`/`Char`; `pionc-v0.17` added Phase 35-A second-class `mut` parameter slot-pointer ABI, `#verify` runtime checks and `#verify` marks in `.pionsig`; `pionc-v0.15` added Phase 27-C1 cross-package monomorphization private lookups, generic closure `%tp_T` capture, native `Map[Int, V]`/`Map[Int64, V]`, and `#derive(Eq)`), ensuring compiler/backend upgrades — including a rebuilt `pionc` whose `qbe` and `libpionrt.a` are unchanged — automatically invalidate stale cache entries. The fingerprint only names cache files: it never changes emitted SSA or objects, so the bootstrap fixed point is unaffected.
- Default directory: `$PION_CACHE_DIR` or `$HOME/.cache/pion/cas`
- Layout:
  - `sig/<sha256>.pionsig`, `sig/<sha256>.pionstub`
  - `ssa/<sha256>.ssa` (persisted for Wasm32 targets and when `--emit-ssa` / `--emit-asm` or `PION_KEEP_NATIVE_SSA=1` is active; Native builds otherwise stage temporary `.ssa` files in kernel-locked per-process directories under `ssa_tmp/` and delete them immediately after `.o` emission, with stale directories from crashed processes reaped automatically on subsequent runs)
  - `obj/<sha256>.o`, `obj/cstub_<sha256>.o`, `obj/cstub_dep_<sha256>.deps`, `obj/rc_<sha256>.res`
  - `bin/<pkg>_<sha256>[.exe]` (indexed as `nativebin:<file>`; fail-closed linked native executable cache requiring safe whitelisted linker flags, no external `-L`/search paths, and no `LIBRARY_PATH`; on Windows, also bypasses caching when any of `LINK`, `_LINK_`, `CL`, or `_CL_` is non-empty or when `LIB` contains any entry outside the system-drive (`%SystemDrive%`, defaulting to `C:`) immutable MSVC / Windows Kits / Microsoft SDKs / LLVM whitelist after canonical path resolution, while the effective link context key incorporates length-prefixed canonicalized `|winlib:` and any non-empty `LINK`/`_LINK_`/`CL`/`_CL_` values for both `nativebin:` and `testmeta:`/`testbin:`)
  - `bin/wasm_<sha256>.wasm` (indexed as `wasmbin:<sha256>`)
  - `testbin/<sha256>` (`pionc test` objects and binaries, indexed as `testbin:<file>`, §5.3)
  - `testmeta/<sha256>.tsv` (`pionc test` source-hash metadata fast path mapping `test_src_key` to `NONE` or `<bkey_file>` + escaped test names, indexed as `testmeta:<sha256>.tsv`, §5.3)
  - `pins/<pid>_<seq>.pin` + `.pin.lock` (kernel-locked per-process live CAS pin files; automatically released on crash/SIGKILL and cleaned by subsequent runs)
  - `index.tsv` (`<key>\t<bytes>\t<last_access_ms>`, keys whitelist-validated via `cas_is_safe_key`; bucket removals verify real directories via `lstat`)
- Eviction: during a command (`build`/`test`/`check`), all HIT/MISS CAS keys are pinned both in-memory and in `$PION_CACHE_DIR/pins/`, preventing intra-batch, cross-phase, and cross-process self-eviction; eviction while recording only removes unpinned LRU entries. After linking, copying outputs, or completing all test child processes, post-run eviction releases the process's own pin, refreshes `last_access_ms` on all keys used by the run, and trims total bytes exceeding `$PION_CACHE_MAX_MB` (default 2048 MB) down to the 80% watermark while never evicting keys pinned by active concurrent `pionc` processes or returned output `keep_keys`.
- **Profiler & bench CAS isolation (§4.3, §5.8, §5.9)**:
  - Native `.ssa` / `.o` keys add `NO_INLINE_RC=1` **only** when `(prof_mask & PION_PROF_RC) != 0` (also forwarded to workspace worker specs). `--profile=cpu` and `--profile=alloc` reuse the regular `--release` `.ssa` / `.o` entries byte-for-byte and only relink against `libpionrt_prof.a`.
  - Linked binary keys (`nativebin:` for `pionc build|run --profile`, `benchbin:` for `pionc bench` runners) include `prof_mask` and the content SHA-256 of the linked `libpionrt_prof.a` (never its size alone). The per-unit `syms` sidecar (§5.9) is cached next to its unit.
  - Wasm32 keys (workspace and single-file) include `wasm_names`, `prof_mask` and the `wasm-opt` tag.
  - On-demand profile runtime builds live in `$PION_CACHE_DIR/rt/`, keyed by `rt_prof_v1:<target>:<cc_ver>:<sysroot>:<flags>:<sha256 of pion_rt.{c,h} and pion_prof.{c,h}>`, always compiled with `-DPION_PROF=1 -fno-omit-frame-pointer` (plus `-mno-omit-leaf-frame-pointer` where supported).
  - The default `libpionrt.a` never contains profiler code (0-byte delta), and no profile or bench artefact is ever written into the source worktree.
- **Invariant**: Running `pionc check`, `pionc build`, or `pionc test` MUST leave `git status --ignored` completely clean inside the source worktree (except an explicitly requested `-o <out>` output binary path).

## 7. Standard Library (`std/`)

Plain Pion packages imported through `pion.toml` (`path` or `git` dependencies); each has `*_test.pion` tests and is `pionc fmt --check` clean.

- **`std/json`**: JSON values, parser and serializer.
- **`std/http`**: HTTP/1.1 over `World` TCP — `parse_request`/`parse_response` (with `Transfer-Encoding: chunked` bodies via `decode_chunked`), `parse_query` (`a=1&b=x%20y` → `Map[String, String]`, percent and `+` decoding), framing helpers `request_len`/`response_len`, `read_http_response`, keep-alive (`should_keep_alive`, where HTTP/1.0 defaults to close; `format_response_ka`/`format_request_ka`/`write_http_response_ka`) and `HttpConn` (`new_conn`, `conn_read_request`, `conn_read_response`), which keeps pipelined bytes between requests on one connection. Existing `Connection: close` APIs are unchanged.
- **`std/net`**: non-blocking event-loop poller (`Poller`, `Event`, `EV_READ`/`EV_WRITE`/`EV_ERR`) over `kqueue` (macOS) / `epoll` (Linux) with `SO_REUSEPORT` multi-worker accept helpers.
- **`std/proc`**: streaming subprocess management (`Child`) and cross-platform pseudo-terminal (`PtyChild`) with `libpionrt.a` `+0 B` (platform C glue in `std/proc/csrc/proc_posix.c` for macOS/Linux and `std/proc/csrc/proc_win.c` for Windows via `[link.<os>] c_sources`). Provides `SpawnOptions` (`cwd`, `env_set`, `env_unset`, `clear_env`), `ReadChunk` (`Data(Bytes)` / `Timeout` / `Eof`), `ExitStatus` (`Exited(Int)` / `Signaled(Int)`), `child_spawn` + independent piped `stdin`/`stdout`/`stderr` streaming & timeout reads, `child_try_wait`/`child_wait`, process-tree cleanup (`child_terminate_tree`/`child_kill_tree` via POSIX `-pgid` and Windows Job Objects), and `pty_spawn`/`pty_read`/`pty_read_timeout`/`pty_write`/`pty_resize`/`pty_wait`/`pty_terminate_tree`/`pty_kill_tree`/`pty_close` (POSIX `posix_openpt` with Linux `EIO -> Eof` handling; Windows dynamic ConPTY + overlapped named pipes + `.cmd`/`.bat` quoting). All OS side-effect APIs take `World`.
- **`std/regex`**: pure-Pion Thompson NFA executed by a Pike VM — linear time in the input for every pattern (no backtracking, no ReDoS). Syntax: literals, `.`, `\d \D \w \W \s \S`, classes `[...]`/`[^...]` with ranges, groups, `|`, greedy and lazy `* + ? {n} {n,} {n,m}`, anchors `^ $`; matching is UTF-8 aware. API: `compile(pattern) -> Result[Regex, String]` (errors carry the byte offset), `is_match`, `find`, `find_at`, `find_all -> Array[Match]` (byte offsets), `replace_all`, `escape`, `program_size`.
- **`std/tls`**: System-native TLS 1.2/1.3 client and server with zero OpenSSL dependency on macOS and Windows, implemented via platform-conditional `[link.linux]` / `[link.macos]` / `[link.windows]` C shims in `std/tls/csrc/` (`+0 B` in `libpionrt.a`):
  - **macOS**: Apple `Network.framework` + `Security.framework` + `CoreFoundation` (`csrc/tls_macos.c`, `-fblocks`); uses the system trust store (honouring `SSL_CERT_FILE` via exclusive anchors) and in-memory `SecCertificateCreateWithData` / `SecKeyCreateWithData` / `SecIdentityCreate` for server mode with zero Keychain writes and zero Homebrew OpenSSL.
  - **Windows**: Windows `Schannel` (`csrc/tls_win.c`, `secur32` + `crypt32` + `ws2_32`); uses the Windows root certificate store (honouring `SSL_CERT_FILE` via an exclusive in-memory `HCERTCHAINENGINE`). Server `tls_listen` returns an explicit unsupported error on Windows Schannel.
  - **Linux**: System OpenSSL (`csrc/tls_openssl.c`, `libssl` + `libcrypto`, default verify paths honouring `SSL_CERT_FILE` / `SSL_CERT_DIR`).
  - **API**: `tls_connect(w, host, port, verify_cert) -> Result[TlsConn, String]` (full DNS + IPv4/IPv6 resolution, SNI, hostname/IP SAN verification, TLS 1.2 minimum), `tls_wrap_fd(w, fd, host, verify_cert) -> Result[TlsConn, String]` (in-place client TLS upgrade of an existing TCP socket, e.g. after HTTP `CONNECT` or `SOCKS5`; transfers `fd` ownership on `Ok`, leaves `fd` unclosed on `Err`), `tls_write`, `tls_write_bytes`, `tls_read`, `tls_read_bytes`, `tls_close`, `tls_protocol`, `tls_cipher`, `tls_version`, `is_ipv4_literal`, and `https_request` on top of `std/http`. Server: `tls_listen(w, host, port, cert_pem, key_pem) -> Result[TlsListener, String]`, `tls_accept(w, listener) -> Result[TlsConn, String]` (client SNI in `conn.host`), `tls_listener_close`, `tls_read_http_request`, `tls_write_http_response`. `std/tls/e2e/run_e2e.sh <pionc>` exercises loopback TLS 1.3/1.2 handshakes, hostname rejection, and `tls_wrap_fd` + `Bytes` I/O; `std/tls/e2e/run_server_e2e.sh <pionc>` drives `examples/https_server` (4 concurrent verified clients, cert/key error paths, Python `ssl` + `curl` clients, exact `/stats`).
